进制：不是手算，是看懂

以前怎么讲

  • 大量手算转换练习
  • 为了应付考试
  • 学完就忘

现在为什么讲

  • 看懂内存地址 0x7fff...
  • 看懂位运算 0xFF & 0x0F
  • 看懂 AI 代码里的位操作
AI 生成的代码里，你经常看到这种写法：
flags = flags | 0x80; // 把最高位设为 1
data = (data >> 4) & 0x0F; // 取高 4 位

不懂进制和位运算，你连它在干什么都不知道，
更别提判断它对不对。

编码：AI 最容易翻车的地方

字符在计算机里，本质上是一个整数。
编码，就是约定俗成的映射规则。

🔤

ASCII

英文世界的标准
一个字符一个字节

🀄

GBK

中文世界的旧标准
一个汉字两个字节

🌍

UTF-8

全球通用
一个汉字三个字节

为什么会有乱码？因为编码和解码用了不同的规则。
AI 处理中文字符串时，经常在这里出错——你得能看出来。

补码：整数溢出与陷阱

为什么用补码？因为它统一了加减法，消除了负零。
但补码也带来了经典陷阱。

AI 生成的代码，可能藏了这个坑：
int a = -1;
unsigned int b = 1;
if (a < b) { ... } // 你以为会进，其实不会

为什么危险

  • -1 在内存里是 0xFFFFFFFF
  • 和 unsigned 比较时，a 被当成一个巨大的正数
  • 结果：-1 > 1

你该怎么做

  • 看到 signed / unsigned 混用，立刻警觉
  • 让 AI 解释这段代码的类型转换
  • 自己写一遍，亲手验证

浮点数：最隐蔽的坑

0.1 + 0.2 ≠ 0.3

你运行这段代码，结果会让你怀疑人生：
float sum = 0;
for (int i = 0; i < 10; i++) sum += 0.1;
printf("%.10f\n", sum); // 0.9999999404

为什么

  • 浮点数用二进制表示
  • 0.1 在二进制里是无限循环小数
  • 存储时被截断，产生误差

怎么用

  • 不要用 == 比较浮点数
  • 用 fabs(a - b) < 1e-6 判断相等
  • 需要精确计算时，用整数或定点数

算法：判断 AI 代码的基础

算法的五个特性，仍然是判断一段代码是否合格的底层标准。

  • 有穷性：步骤有限，不能无限循环。
  • 确定性：每一步含义明确，不能有歧义。
  • 可行性：每一步都能实际执行。
  • 输入：有零个或多个输入。
  • 输出：有至少一个输出。

AI 给你的代码，你拿这五条去套——
过不了，就不是合格算法，哪怕它能跑。

流程图：弱化画图，强化拆解

以前

  • 花大量时间手画流程图
  • 记各种图形符号
  • 画完就扔，跟代码脱节

现在

  • 用自然语言描述步骤
  • 让 AI 生成流程图
  • 你检查 AI 的图对不对

核心能力不是画图，是把问题拆解成可执行步骤。
你能拆清楚，AI 才能生成对；你拆不清楚，AI 也帮不了你。

你的第一个程序：

return 0;
}

重点不是这一行代码，而是从源码到可执行文件的完整过程。
这个过程，AI 替不了你理解。

故意犯几个错，学会读错误信息

❌ 少了一个分号
printf("Hello, World!\n")
❌ 函数名拼错了
print("Hello, World!\n");
❌ 忘记包含头文件
// 没有 #include <stdio.h>

编译器报的错，是你和计算机对话的方式。
学会读错误信息，比学会写正确代码更重要。
