已经学过的知识点
  • 变量与类型一个名字存放一个值，如 int x = 72;
  • 输入与输出scanf 取地址读入，printf 按格式输出
  • 分支与循环if 决定走哪条路，for 决定重复多少次

共同的局限 这些工具都在处理单个数据。五十个成绩就要五十个变量，而变量名无法用循环生成：循环变量 i 取不到 s1、s2 这样的名字。
由此提出的要求 需要一种“一次声明、批量存放、按下标统一处理”的构造。这就是数组。
引例：求高于平均分的人数
任务与步骤
读入五十名学生的成绩（0 至 100 的整数）
先求五十个成绩的平均分
再数高于平均分的人数，并输出
这是本章的出发点 程序的规模一旦超过“几个数”，就必须有批量存放、统一处理的手段。
先求平均分并不难
int s, sum = 0, i;
for (i = 0; i < 50; i++) {
    scanf("%d", &s);
    sum += s;  /* 只累加，不保存 */
}
double avg = (double)sum / 50;
接着就卡住了 要数“高于平均分的人数”，必须把这五十个数再逐个比较一遍。但它们读入后没有保存，只剩一个 sum；变量名是标识符，也无法在循环中按下标生成。

术语 方括号中的数字称为下标（或索引）。数组元素指其中某一格，数组长度指格子的总数。
数组长度：编译期常量与运行期变量
写法一：编译期确定长度
#define N 5
int a[N];          /* 符号常量 */
int b[5];          /* 字面常量 */
#define 与字面常量给出编译期常量，数组长度在编译期确定；int a[5] 是本讲最常用的写法。
写法二：运行期确定长度（VLA）
int n;
scanf("%d", &n);
int a[n];        /* 长度运行时确定 */

const int M = 5;
int d[M];        /* 也是 VLA */
① 变长数组的用法 先读入 n，再写 int a[n]：长度在运行时确定，这就是变长数组（VLA）。C99 起纳入标准，gcc 可用；C11 起列为可选特性，MSVC 不支持。PTA 中很常见，要能读懂。
② const 的用法 C 中 const int M = 5; 声明的是只读变量，不是常量表达式。块作用域中的 int d[M] 同样属于 VLA，长度也在运行时确定。
工程口径 在线评测按题目要求使用 VLA 没有问题；工程上更常用固定容量 + 实际个数：先声明足够大的数组（如 int a[100];），另设变量 n 记录当前实际元素个数。VLA 长度由输入决定，输入过大可能栈溢出。本讲统一以 int a[5] = {72,78,85,90,96}, n = 5; 为例，容量与个数分离。

连续 五个元素占据一段不间断的内存，中间没有空隙。
等距 每个 int 通常占 4 字节，相邻地址相差 4。地址由系统运行时分配，具体数值每次可能不同，此处取某次实际运行的结果。
可计算 已知首地址与下标即可算出：地址(a[i]) = 首地址 + i × 4
伏笔 地址可计算，因此函数只拿到首地址就能访问整组元素，第四部分将以此为核心。
与独立变量的根本差别 i 是变量，可随循环变化；写 s25 时名字写死。因此五十个成绩能用同一段循环逐个处理。访问 a[0] 与 a[4] 也只需一次地址计算，耗时相同。

关键认识 a[i] 是一个普通变量：可以读、可以写、可以参与运算、可以作函数实参，用法与 int 变量完全相同。区别只在于它的名字由“数组名 + 下标”构成。
初始化的四种写法
int a[5] = {1, 2, 3, 4, 5};   /* ① 全部给出 */
int b[5] = {1, 2};            /* ② 其余补 0 */
int c[]  = {1, 2, 3};         /* ③ 长度为 3 */
int d[5];                     /* ④ 元素值不确定 */
①五个元素依次赋值为 1 至 5。
②前两个为 1、2，其余三个自动补 0。
③方括号内留空，长度由初值个数决定，此处为 3。
④未给出初始化列表，局部变量的元素内容不确定，可能是任意值。
补零的适用条件 只有在给出了初始化列表时，未写出的元素才补 0。写法 ④ 没有列表，因此不补。
初值个数不可超过长度 int a[3] = {1, 2, 3, 4}; 编译即报错。这是数组少数能在编译期被发现的问题，其余多数要等到运行才暴露。
越界不报错
int a[5] = {1, 2, 3, 4, 5};
a[5] = 10;        /* 编译通过，运行时不作检查 */

读到无关数据

取得的字节与本数组无关，输出的数值异常，但程序继续运行。

覆盖相邻变量

写入落到别的变量所占的单元上，该变量被悄悄改掉，错误出现在别处。

触发段错误

偏移过大，访问到无权访问的区域，操作系统终止该进程。

性质 越界访问属于未定义行为。标准不对其后果作任何规定，同一段代码在不同环境下可能表现不同，因此不能依赖任何观察到的结果。
防范 编译器不作检查，只能由程序员保证。关键是把循环上界与最大合法下标对齐：从 0 开始遍历时，写 i < n 或 i <= n − 1 都可以；写成 i <= n 才会访问 a[n] 而越界。

三题的共同点 第 1、2 题考初始化规则，第 3 题考下标范围。这两处是数组定义阶段出错最集中的地方，且编译器都不作提示。
第 1 题　a[3] 的值

结果为 0。给出了初始化列表，未写出的 a[2] 至 a[4] 全部自动补 0。

对比：int a[5]; 没有初始化列表，a[3] 的值不确定。两者的差别仅在于大括号的有无。

第 2 题　数组长度

长度为 4。方括号留空时，编译器按初值个数确定长度。

这种写法的好处是增删初值不必同步修改长度；代价是长度不再显式可见，阅读代码时需要数一遍。

第 3 题　循环上界

数组定义为 int a[5] = {1,2,3,4,5}，合法下标只有 0 至 4。i <= 5 使循环在 i = 5 时仍执行一次，写入 a[5]，越过了数组末尾。

for (i = 0; i < 5; i++)      /* 访问 a[0] 至 a[4] */
for (i = 0; i <= 4; i++)     /* 等价写法 */

该错误编译时无提示，运行时通常也不报错，因此必须靠书写时核对。

遍历的固定骨架
int a[10] = {72, 78, 85, 90, 96}, n = 5;   /* 容量 10，实际 5 个 */
int i;
for (i = 0; i < n; i++)
    /* 处理当前元素 a[i] */;

1起点

i = 0　从第一个元素开始，不是从 1 开始。

2条件

i < n　与 i <= n−1 等价；写成 i <= n 会越界访问 a[n]。

3步长

i++　逐个前进，不跳格。

本讲的其余内容都建立在这一段之上 求和的差别只在循环体多一句 sum += a[i];；求最值的差别只在循环体多一个 if。骨架不变，变的是循环体。
长度 n 与容量分开 上面 a[10] 是容量，n = 5 是当前实际存放的个数，循环只遍历前 5 格。若由输入读入，读入时同步计数。
求和与最值：同一骨架

int i, sum = 0;
for (i = 0; i < n; i++) {
    sum += a[i];
}
double avg = (double)sum / n;
总和 = 421 平均 = 84.20
int max = a[0];

两处初值 sum 从 0 起累加；max 必须取真实元素 a[0]，若写成 0，全为负数时结果恒为 0。

应用：把最高分换到第一位
应用场景 给定 a[5]={72,78,85,90,96}，要求把最高分换到第一位：先找出最高分的位置 pos，再交换 a[0] 与 a[pos]。这个场景需要的是位置，不是分数——其实有了下标，也就可以得到值。
写法一：值与位置一起记
int i, max = a[0], pos = 0;
for (i = 1; i < n; i++)
    if (a[i] > max) {
        max = a[i];
        pos = i;
    }
/* 交换 a[0] 与 a[pos] */
两个量必须同时更新：只改 max 不改 pos，交换时用的是旧位次。
写法二：只记位置
int i, pos = 0;
for (i = 1; i < n; i++)
    if (a[i] > a[pos]) pos = i;

/* 交换 a[0] 与 a[pos] */
本场景只要 pos 就能完成交换，不必另存分数。
逆序：首尾交换
int a[5] = {72, 78, 85, 90, 96}, n = 5, i;
for (i = 0; i < n / 2; i++) {
    int t = a[i];
    a[i] = a[n - 1 - i];
    a[n - 1 - i] = t;
}
循环到 n/2 为止 写成 i < n 会把每对元素交换两次，数组恢复原状。中间元素无需处理。

与下一部分的联系 逆序是“在数组内部调整元素位置”的最简形式。插入与删除做的是同一件事，只是移动方向不同、移动的是一段而不是一对。
遍历统计：四步模板
步骤要做的事常见错误
1 定长度明确 n 是元素个数，不是容量把 MAX 当作 n 使用，遍历到未使用的格子
2 建循环for (i = 0; i < n; i++)写成 i <= n，越界一格
3 设初值累加用 0，最值用 a[0]，计数用 0最值初始化为 0，全负数时结果错误
4 写循环体只做一件事：读 a[i]，更新一个结果在循环体内修改 i，破坏遍历
适用范围与顺序 这四步针对遍历统计：逐个读 a[i]，汇总出一个结果（和、最值、个数、位置）；插入与删除要搬动元素，用的是另一套思路。顺序不可颠倒：先定范围，再写循环，最后填循环体；其中初值由任务决定，最需理解。
检查方法 用最小的例子手算一遍：n = 1 时循环执行几次？n = 0 时会不会访问 a[0]？这两个边界能暴露绝大多数错误。

三题指向同一件事 第 1、3 题考初值，第 2 题考边界。遍历类算法的错误几乎全部落在这两处，而不在循环体本身。
第 1 题　max 的初值

当全部元素都为负数时结果错误。例如 {-5, -3, -8}，真实最大值为 −3，而 max = 0 从未被替换，输出 0。

正确写法是 max = a[0]，并让循环从 i = 1 开始，因为第一个元素已经作为初值参与过比较，不必再比一次。

第 2 题　逆序循环的上界

数组恢复原状。以 {1, 2, 3, 4} 为例：

i=0: 交换 a[0] a[3] → 4 2 3 1
i=1: 交换 a[1] a[2] → 4 3 2 1
i=2: 交换 a[2] a[1] → 4 2 3 1
i=3: 交换 a[3] a[0] → 1 2 3 4   /* 回到原样 */

每一对元素被交换两次，等于没有交换。上界应为 n / 2。

第 3 题　未初始化的累加器

结果不确定。sum 的初始内容是内存中的残留值，累加等于在一个任意数上继续加。

这类错误的特点是：可能偶尔得到看似正确的答案，换一台机器或换一次编译就变了。“有时对”是未初始化变量最典型的症状。

有序表的维护
场景
成绩表按分数升序存放。此时录入一名新学生，数据必须插入到中间某处；删除一条记录，后面的数据必须移位。
难点与前提 数组长度在声明时固定，元素之间没有空隙。插入的前提是还有空余位置（容量大于当前个数 n）：先把后面的元素逐个右移腾出位置，再写入新值。删除则是抹掉一个位置后左移补齐。
操作元素如何移动起点
插入从插入点起整体右移一位末尾
删除从删除点起整体左移一位删除点
方向为什么相反 右移必须自后向前，否则先写会覆盖尚未移动的数据；左移必须自前向后，理由相同。
本部分的两个函数 insert 与 removeAt。两者都不改变数组的容量，只改变其中有效元素的个数 n，并把这个新长度返回给调用方。

② 后移

③ 写入

若从前往后找插入点 从 a[0] 向右扫，第一个大于 25 的元素（30，a[2]）即插入点，结果相同。但定位后仍须从后往前移动：查找方向可选，移动方向不能改。
顺序不可颠倒 必须先移动、后写入。若先执行 a[2] = 25，原来的 30 已被覆盖，再也无法后移。
代价 最坏情况（插在首位）需要移动全部 n 个元素，与 n 成正比。这是数组“连续存放”换来的代价。

插入的三种边界
情形移动情况结果
插最小值 5全部 4 个元素各后移一位，i 减到 −15 10 20 30 40，插入位置 a[0]

第四种情形：表已满 容量 MAX 是格子总数，n 是已存个数。n == MAX 时没有空位，不能插入：保持数组与 n 不变，并给出提示。 
if (n >= MAX) printf("表已满，不能插入\n");
else { /* 后移、插入，再 n++ */ }
下一页做什么 把这四种情形写进一个函数：传入数组、当前个数与待插值，返回新的个数。这页先把边界想清楚，函数写法见下一页。
插入函数与 main 调用
函数定义：先查容量，再插入
#define MAX 10
int insert(int a[], int n, int x) {
    int i;
    if (n >= MAX) return n;  /* 已满 */
    i = n - 1;
    while (i >= 0 && a[i] > x) {
        a[i + 1] = a[i];
        i--;
    }
    a[i + 1] = x;
    n++;
    return n;
}
main 中调用
int main(void) {
    int a[MAX] = {10,20,30,40};
    int n = 4, i;
    n = insert(a, n, 25); /* 插入更新 n */
    for (i = 0; i < n; i++)
        printf("%d ", a[i]);
    return 0;
}
运行结果 输出 10 20 25 30 40，n 由 4 变为 5。
为什么必须返回新长度 数组传进去后，函数内对元素的改动在 main 中可见；但 n 是普通变量，按值传递，函数里的 n++ 不会影响调用方。所以要写 n = insert(a, n, 25);。

① 覆盖
a[k] = a[k+1]，后一个元素前移一位
② 推进
下标递增，把后续元素逐个前移，直到末尾
③ 缩短
长度减 1，最后一位不再属于有效数据
方向与插入相反 删除必须自前向后：先 a[2]=a[3]，再 a[3]=a[4]。若反过来，先写 a[3]=a[4] 会把 40 覆盖成 50；再写 a[2]=a[3] 时读到的已是新值 50，于是 50 被重复写入，30 和 40 都丢失。
最后一位怎么办 无需清理。长度减 1 之后，那一格的内容不再参与任何运算，保留原值不影响结果。

按位置删除元素的函数
int removeAt(int a[], int n, int k){
    int i;
    if (k < 0 || k >= n)
        return n;          /* k 不是合法下标，原样返回 */
    for (i = k; i < n - 1; i++)  /* 从位置 k 起，后面的元素依次左移 */
        a[i] = a[i + 1];
    return n - 1;          /* 只删除一个元素，长度减 1 */
}
循环上界 i < n - 1。循环体访问 a[i+1]，当 i = n−1 时会读到 a[n]，越界。
位置合法性必须自行检查 k 是下标，须满足 0 ≤ k < n，编译器不检查。删首元素 k=0 时移动量最大；删末元素 k=n−1 时循环体一次也不执行，仅长度减 1。

int delOne(int a[], int n, int x){
    int i, j;      /* 读、写位置 */
    for (i = 0; i < n; i++){
        if (a[i] != x) continue;
        for (j = i; j < n - 1; j++)
            a[j] = a[j + 1];
        return n - 1;  /* 删到一个 */
    }
    return n;
}
void printArr(int a[], int n){
    int i;
    for (i = 0; i < n; i++)
        printf("%d ", a[i]);
    printf("\n");
}
main：反复调用直到删完
int main(void){
    int a[1000], n, m, i, old, del = 0;
    /* 读入个数、各元素、待删值 */
    scanf("%d", &n);
    for (i = 0; i < n; i++)
        scanf("%d", &a[i]);
    scanf("%d", &m);
    old = n;                     /* 删前长度 */
    while (1) {
        n = delOne(a, n, m);     /* 删一个 */
        if (n == old) break;  /* 没删到 */
        del++;  printArr(a, n);
        old = n;
    }
    if (del == 0)  /* 无匹配 */
        printArr(a, n);
    return 0;
}

三题的共同点 它们都不会导致编译错误。前两题是边界问题，第三题是接口使用问题：程序能运行，结果错误。
第 1 题　条件的先后顺序

&& 从左向右求值。当 i 减到 −1 时，先算 a[-1] > x，确实读了数组之前的内存，属于越界读取。

为什么看起来没事：紧接着的 i >= 0 为假，循环随即结束，越界读到的值没有参与后续比较，本题结果通常仍然正确。但这仍是未定义行为：那格内存若不可读，程序就可能异常终止。结果碰巧对，不等于写法对。

正确顺序是 i >= 0 && a[i] > x：先确认下标合法，再访问元素，靠短路求值避开越界。这个习惯适用于所有“带下标的循环条件”。

第 2 题　删除的上界

会读到 a[n]，即数组末尾之后的一格，属于越界。

for (i = 0; i < n; i++)
    a[i] = a[i + 1];   /* i = n-1 时读 a[n] */

上界应为 i < n - 1。判断依据很简单：循环体中出现了 a[i+1]，上界就要相应减 1。

第 3 题　未接收的返回值

数组内容确实改变了，元素已左移；但调用方的 n 仍是旧值。此后按旧长度遍历，会把最后那个无效的重复元素当成有效数据输出。

n = removeAt(a, n, 2);   /* 正确：长度同步更新 */

函数的返回值是唯一的沟通渠道。这与下一部分“长度为什么必须单独传递”是同一件事的两面。

要点结论
定义int a[N];　N 为常量；容量在编译期确定
下标合法范围 0 至 n−1；越界属未定义行为，编译器不检查
初始化给出列表时不足补 0；未给列表时元素值不确定
遍历for (i = 0; i < n; i++)　初值由任务决定
插入从右往左腾位，元素依次右移；空位写入新值，n 加 1 后返回
删除从删除位置起，后面的元素依次左移补位，返回 n−1
最容易出错的三处 循环上界写成 <=；最值初值写成 0；插入删除后丢弃新的 n。三处均不报编译错误。
