int main(void){

本部分的路线 先看清数组名的值（地址），再看调用时这个值如何被复制，最后观察函数内的修改为何能在 main 中体现。
先读懂声明 s[100] 中的 100 是容量上限，即最多放 100 个元素；n 是当前实际存放的个数。数组按容量分配空间，循环只按 n 遍历。
现象 六个操作堆在一个 main 里：单独验证求和也得连读入一起跑；改一处要在几十行里找，出错难定位。
目标 一个操作一个函数：读入、求和、最值、插入、删除、输出。main 只负责按顺序调用。

数组名的值 a 的值是首元素的地址，即 0x61FE30。它不代表某一个元素的内容，而代表这一组数据的起点。
与取地址的关系 a 与 &a[0] 的值相同。写 &a[0] 是显式取首元素地址，写 a 是它的简写。
由此可以解释一个现象 printf("%p", a) 输出的是一串地址，而不是整组数据。数组名在参与运算时，交出的是地址。

下标与序号 a[i] 指自首地址起向后第 i 个元素：下标是偏移量。
日常说的序号从 1 开始，第 k 个元素的下标是 k−1；a[0] 就是第 1 个。

副本与原件的关系 副本是地址，不是数据。两份地址指向同一处，因此写入落在同一处。“传值”这一规则并没有被破坏，改变的只是所传之值的类型：从数值变成了地址。
用途 “清零”“逆序”这类改造整组数据的工作都依赖这一机制；返回值无法带回整组。

区别 普通参数传的是数值，数组参数传的是地址值；两者都是传值，只是值的含义不同。
数组名代表首元素地址
写法是否合法原因
a = b;不合法数组名代表固定的一组存储单元，不能整体赋值；复制元素要逐个进行
a++;不合法数组名不能自增；要访问下一个元素，写 a[1]
&a[0]合法取首元素地址，与 a 参与运算时交出的地址相同
a[0] = 5;合法元素可以单独赋值；不可整体赋值的是数组名
准确的表述 此处 a 是 main 中定义的数组名：它代表这一组存储单元，参与运算时交出的是首元素的地址 0x61FE30。
数组名不能整体赋值或自增；把数组交给函数时，形参 int a[] 接收到的也是这个首地址，函数内用 a[i] 访问各个元素。
由此产生的两个常见错误 一是用 a = b; 试图复制整个数组（应逐元素赋值）；二是把数组交给函数后，在函数内用 sizeof(a) 求元素个数——这里得到的是一个地址的大小，不是元素个数，长度必须另行传入。
元素个数必须单独传递
✗ 错误的写法
void show(int a[]){
    int i, n = sizeof(a) / sizeof(a[0]);
    for (i = 0; i < n; i++)
        printf("%d ", a[i]);
}
结果 算出的 n 是 2（64 位环境）或 1（32 位环境），不是 5。原因是形参 a 是指针变量，它得到的是调用方传来的首地址，sizeof(a) 算出的是这个变量本身的大小，不是数组长度。
✓ 正确的写法
void show(int a[], int n){
    int i;
    for (i = 0; i < n; i++)
        printf("%d ", a[i]);
}
调用 show(a, 5);　长度由调用方明确告知，函数内不再猜测。
根本原因 函数只拿到首地址，而首地址不含长度信息。长度是独立信息，必须独立传递：这正是本部分所有函数都带 n 的原因。
引申 数组参数包含两个量：起点与长度，缺一不可。函数要处理数组，就必须把长度一起传入。
形参的三种写法
void f1(int a[], int n);          /* 最常用：方括号留空 */
void f2(int a[5], int n);        /* 5 被忽略 */
void f3(int a[MAX], int n);      /* 同样被忽略，但有文档价值 */
void f4(const int a[], int n);    /* 函数体内不能修改元素 */
写法编译器如何看待
int a[]接受一个地址，具体长度由调用方另传
int a[5]与上一行完全相同，5 不产生任何约束
const int a[]函数内不得通过 a 修改元素，违反则编译报错
const 的作用 写 int a[5] 不能限定函数只接受 5 个元素，方括号中的数字在形参位置被忽略。加上 const 后，函数体内不能通过 a 修改元素，违反会在编译期报错；同时也表明本函数不修改调用方的数据。
重构后的 main
int main(void){
    int s[MAX] = {72, 78, 85, 90, 96}, n = 5;

    show(s, n);                                                   /* 输出全部 */
    printf("总和 %d\n", sumOf(s, n));                    /* 求和 */
    printf("平均 %.2f\n", average(s, n));                /* 求平均 */
    printf("最高 %d，第 %d 位\n", maxOf(s, n), posOf(s, n));  /* 最高分及位置 */

    n = insert(s, n, 88);                              /* 插入 88 */
    n = removeAt(s, n, 0);                             /* 删除首元素 */
    show(s, n);                                                   /* 再看结果 */
    return 0;
}
变化 变量由十余个减为两个，main 中不再出现循环。每一行都在说明做什么，不涉及怎么做。
扩展方式 需要新增“求最低分”，只需写一个函数并加一行调用。main 的其余部分不受影响。
两处必须保留 n = 不能省，插入与删除都会改变长度；每次调用都要同时给出数组与长度，两者成对出现。
完整案例：一次操作序列
操作n数组内容
初始572　78　85　90　96
insert(s, n, 88)672　78　85　88　90　96

长度是主线 每次插入或删除，数组内容变了，n 也变了。后续每一次计算都必须使用新的 n，否则会统计到无效数据。
容量是上限 数组自始至终是 s[MAX]，占用的空间不变。n 记录当前用了多少格，插入时必须检查 n 不能超过 MAX。
一句话概括本讲 数组名给出起点，长度给出范围，函数按这两条信息操作同一组存储单元。三件事说清，数组的应用就立住了。

三题构成一条判断链 第一题问“能否改到”，第二题问“为什么另一种改不到”，第三题问“函数到底知道多少”。三题都能答对，就说明地址这一层已经通了。
第 1 题　数组参数

变为 1。形参 a 得到的是首地址的副本，副本指向 main 中的那组存储单元，因此 a[0] = 1 写的就是同一处。

注意：函数没有返回值，也没有使用 &，却改变了调用方的数据。这正是数组参数与普通参数的根本差别。

第 2 题　普通参数

没有变。形参 x 是实参值的一份副本，两者位于不同的存储单元。函数内对 x 赋值，只改副本。

两者的规则是同一条：形参总是实参值的副本。差别在于实参值本身是一个数，还是一个地址。

第 3 题　函数内的长度

不能。函数内的 a 是一个地址，sizeof(a) 得到的是地址的大小（64 位环境为 8），不是整组数据的字节数。

/* main 中：20 / 4 = 5　正确 */
/* 函数内： 8 / 4 = 2　错误 */

结论：元素个数必须由调用方作为参数传入，函数内无法自行求出。

排序与查找：两个新任务
为什么引入新方法
排名 求最大值只需记住一个数；要给出“谁第二、谁第三”，就得把整组数据按次序排列。
查找效率 顺序查找逐个比较就能完成任务；数据量大时比较次数多。若数据有序，可用二分查找减少比较次数。
本部分要学的四种方法
1比较法排序
两数相比，次序不对就交换；最容易想到。
2选择法排序
先找出最小者的位置，每轮只交换一次。
3冒泡法排序
相邻两数比较，一轮把最大者推到末尾。
4二分查找
取中点比较，一次砍掉一半；前提是数据有序。
按功能选择方法 排序解决“按次序排列”，查找解决“定位某个值”，是两项独立任务。只有采用二分查找时才要求数据有序；用顺序查找时，数据是否有序都可以。
比较法排序：逐个比较，发现更小就换
先看第一趟 目标是从小到大。先固定 a[0]=78，让它与后面每个数比：与 a[1]=92 比，78 更小，不动；再与 a[2]=65 比，78 更大，当场交换。
换完还没结束 换过来的 78 留在 a[2]，这一趟还没完：继续用 a[0] 与 a[3]、a[4] 比，都不用换。a[0]=65 是全部五个数中最小的，位置定下来了。
下一趟照样做 让 a[1] 和它后面的每个数比，做法完全相同。每做完一趟就固定一格，i 从 0 走到 n−2；前 n−1 格排好后，最后一格自然是最大的。

选择排序：每轮挑一个最小的
for (i = 0; i < n - 1; i++) {
    k = i;                  /* 假定 i 最小 */
    for (j = i + 1; j < n; j++)
        /* 只记位置，不交换 */
        if (a[j] < a[k]) k = j;
    if (k != i) {           /* 一轮换一次 */
        t = a[i]; a[i] = a[k]; a[k] = t;
    }
}
内外两层各管什么 外层定“该轮到第几位”，内层在这一位之后找最小者的下标。找完再换，不是边走边换。

选择排序：封装成函数
void selectionSort(int a[], int n){
    int i, j, k, t;
    for (i = 0; i < n - 1; i++) {
        k = i;
        for (j = i + 1; j < n; j++)
            if (a[j] < a[k]) k = j;
        if (k != i) {
            t = a[i]; a[i] = a[k]; a[k] = t;
        }
    }
}
无需返回新数组 函数改的是 main 中的那组存储单元，调用处不必接收结果。

比较法与选择法对照
比较法：边比边换
for (i = 0; i < n - 1; i++)
    for (j = i + 1; j < n; j++)
        if (a[i] > a[j]) {
            t = a[i]; a[i] = a[j]; a[j] = t;
        }
特点 一发现更小就交换，一轮可能换好几次。只用一个 if，最好懂；交换次数多。
选择法：先定位再换
for (i = 0; i < n - 1; i++) {
    k = i;
    for (j = i + 1; j < n; j++)
        if (a[j] < a[k]) k = j;
    if (k != i) {
        t = a[i]; a[i] = a[k]; a[k] = t;
    }
}
特点 先记住最小者的下标，扫完只换一次。多一个变量 k，但交换次数少。
同一组数据：78　92　65　88　71 比较法交换 6 次，选择法只交换 2 次；比较次数两者相同（各 10 次）。差别只在“什么时候换”：边比边换，还是记下位置最后换一次。
冒泡排序：大的往后挪
for (i = 0; i < n - 1; i++)
    for (j = 0; j < n - 1 - i; j++)
        if (a[j] > a[j + 1]) {
            t = a[j];
            a[j] = a[j + 1];
            a[j + 1] = t;
        }
一轮下来得到一个最大值 从左到右两两比较，大的始终往右挪，一轮结束时最大值必然停在末位。
内层上界为什么减去 i 末尾已有 i 个元素归位，再比就是空转。n - 1 - i 保证 j + 1 不越过 n - 1。

与选择排序的差别 选择排序把“找最小”和“交换”分成两步，一轮只换一次；冒泡排序边走边换，一轮可能换很多次。比较次数相同，交换次数不同。
冒泡排序：加一个提前结束
void bubbleSort(int a[], int n){
    int i, j, t, flag;
    for (i = 0; i < n - 1; i++) {
        flag = 0;             /* 换过否 */
        for (j = 0; j < n - 1 - i; j++)
            if (a[j] > a[j + 1]) {
                t = a[j];
                a[j] = a[j + 1];
                a[j + 1] = t;
                flag = 1;
            }
        if (flag == 0) break;   /* 无交换 */
    }
}
flag 的作用 一轮下来一次交换都没有，说明每一对相邻元素都已按序，整组数据已经排好，后面的轮次可以全部省去。
本例的实际轮次 第一轮把 92 送到末位，第二轮把 88 送到倒数第二位，第三轮只换了一次，第四轮无交换即退出。
不能省略外层 flag 只是提前退出，外层循环的上界仍要写 n - 1；最坏情况是逆序，需要跑满。

标志量能否提前退出不能：一轮没交换只说明当前 a[i] 最小，后面仍可能无序不能：k == i 只说明当前 a[i] 最小，后面仍可能无序能：一轮相邻都不交换，整组已有序
冒泡为什么能 内层比较的是相邻元素。某轮一次都没交换，说明 a[0] ≤ a[1] ≤ … ≤ a[n−1−i]；右端又是前几轮排好的较大元素，整组有序，可以 break。
另两种为什么不能 比较法、选择法一轮“没动作”，只说明当前 a[i] 是剩余部分最小，并不保证后面的元素已按序。例如 1、3、2、4 第一轮都不交换，但整组仍无序。真要提前退出，只能另做一趟相邻有序检查。
量级与取舍 三者比较次数都是 n(n−1)/2，交换次数随数据而变，表中数字只对应本例。比较法边比边换，选择法少交换，只有冒泡能靠标志量省去后续轮次。
二分查找：每次砍掉一半
唯一的前提 数组必须已经有序。无序时，“中点左边都更小”这一依据不成立，二分立刻失效。

mid = (low + high) / 2

每次砍掉一半 十个数最多比较四次就能定位。有序是利用二分查找的前提。
二分查找：返回下标
函数：在区间里反复取中点
int binarySearch(int a[], int n, int x){
    int low = 0, high = n - 1, mid;
    while (low <= high) {
        mid = (low + high) / 2;
        if (a[mid] == x) return mid;
        if (a[mid] < x) low = mid + 1;
        else high = mid - 1;
    }
    return -1;
}
运行结果：6　−1 （96 在下标 6；80 不在数组中）
main：调用两次
int main(void){
    int a[10] = {65,71,78,85,88,
                         92,96,98,99,100};
    int r1 = binarySearch(a, 10, 96);
    int r2 = binarySearch(a, 10, 80);
    printf("%d %d\n", r1, r2);
    return 0;
}
返回值有两种含义 0 至 n−1 是找到的下标，−1 是未找到。调用处必须先判断，再使用这个下标。
边界必须移动 写成 low = mid 或 high = mid 会卡住：区间只剩一格时 mid == low == high，边界与 mid 都不再变化，循环条件一直成立。必须写成 mid ± 1，区间才能真正缩小。

三题指向同一件事 排序与查找的正确性都建立在区间与边界上：比较的对象是谁，循环的上界到哪里，区间是否真的在缩小。
第 1 题　写错比较对象

排序失败。k 会变成“比 a[i] 小的最后一个元素的下标”，而不是最小者的下标。

/* 78 92 65 88 71，i = 0 */
j = 2：65 < 78，k = 2
j = 4：71 < 78，k = 4   /* 覆盖了正确的 2 */
交换 a[0] 与 a[4]：71 92 65 88 78

正确写法必须拿候选者与当前最小值比，即 a[k]，因为 k 会随扫描不断前移。

第 2 题　内层上界写错

下标越界。当 j = n − 1 时，a[j + 1] 就是 a[n]，已在这一组数据之外。

C 语言不检查下标，程序多半照常运行，可能改坏相邻的变量却不报错。越界属于未定义行为：可能出错，也可能看起来正常。

正确上界是 n − 1 − i，既避免越界，也免去对已归位元素的空转比较。

第 3 题　对无序数组二分

不能。二分的每一步都以“中点左侧都小于中点、右侧都大于中点”为依据，无序时这个依据不成立，正确的元素可能落在被舍弃的那一半里。

/* 未排序：92 65 78 88 71，查 65 */
mid = 2，a[2] = 78 > 65 → high = 1
区间缩到 [0,1]，65 在 a[1] … 本例侥幸命中
/* 换成 71 65 78 92 88，查 65：mid 舍去左侧即丢失 */

结论：先排序，再二分。顺序不重要，前提不能省。

要点结论
传参传首地址的副本；元素个数另行传入，函数内改元素调用方可见
数组名代表首地址，不可赋值、不可自增
比较法排序固定 i，依次与后面元素比较，更小就交换
选择排序每轮记最小下标 k，最后只交换一次
冒泡排序相邻两两比较，大的右移；加 flag 可提前结束
二分查找与中点比较舍弃一半；返回下标或 −1，前提是已有序
最容易出错的三处 函数里用 sizeof(a) 当元素个数；冒泡内层上界写成 n；二分边界写成 mid 而不加 1 或减 1。三处均不报编译错误。
