为什么程序需要“选择”？
核心问题 程序能否像人一样，根据不同情况做出不同反应？比如：余额充足才支付、成绩≥60 才合格……
这种“如果…就…否则…”的思维，就是选择结构。
本章基石 选择结构的本质是对条件的判断。
判定条件：真与假
条件表达式 用运算符把操作数连成的式子，作为运算数：非 0 即“真”、为 0 即“假”。
表示运算结果：真用 1 表示，假用 0 表示。
🧭比喻 条件表达式像一道判断题：程序看答案是“是”(1) 还是“否”(0)，来决定走哪条路。
关键认知 早期 C 没有专门的布尔类型，用整数 1/0 充当真假，自 C99 起新增了布尔类型 _Bool 。
－ C99 新增内置类型关键字 _Bool，专门表示布尔值；
　　· _Bool 对象只能取 0 或 1，任何非零值赋给它都会变成 1；
－ 头文件 <stdbool.h> 没有定义 _Bool，而是用宏提供别名：   #define bool _Bool
　　　#define true 1　　　#define false 0
－ 所以 bool 是 _Bool 的宏别名，true/false 就是 1/0；
关系运算符一览（6 个）
运算符含义示例结果结合方向
<小于3 < 51自左向右
<=小于等于5 <= 51自左向右
>大于3 > 50自左向右
>=大于等于5 >= 31自左向右
==等于3 == 50自左向右
!=不等于3 != 51自左向右
要点 ① 结果只有 0（假）或 1（真）；
　　 ② 优先级低于算术运算：a > b + 1 等价于 a > (b+1)；
　　 ③ == 是两个等号，别写成赋值 =。
关系运算符示例
int a=3, b=2, c=1, d, f;
d = a > b;        // 3>2 为真
f = a > b > c;   // 注意结合方向！

➤ a > b → 1 　　d = a > b → d = 1 ➤ a > b > c → (3>2)=1, 再 1>1 = 0 → f = 0
易错提醒:
- a > b > c 不是数学的“a 大于 b 大于 c”！
- C 中, 从左到右算：先 (a>b)=1，再 (1 > c) , 即 1 > 1 = 0。
- 要表达“a>b 且 b>c”必须用逻辑与：(a > b) && (b > c)。

运算符名称含义示例结果

记忆口诀
- && 像“串联开关”：一个断全断；
- || 像“并联开关”：一个通全通；
- ! 像“反相器”：真变假、假变真。
逻辑运算符示例
int a = 4, b = 5;
printf("%d\n", !a);      // a真→取反
printf("%d\n", a && b);  // 都真
printf("%d\n", a || 0);  // 一真即真
printf("%d\n", !a || b);
0 　　　　// 4 是非 0，视为“真” 1 　　　　// a && b = 真 = 1 1 　　　　// a || 0 = 真 = 1 1 　　　　// !a || b = 真 = 1
逻辑短路求值（一）
什么是短路
&&：左边为假，右边不再计算（结果已定假）；
||：左边为真，右边不再计算（结果已定真）。 
int i = 0, j = 5;
// 安全：i==0 为假，j/i 这个危险除法不会执行！
if (i != 0 && j / i > 2) {
    // ...
}
生活中的短路 ① “先看有没有，再决定要不要”
先问“你带伞了吗？”——没带，就不用再问“能不能借给我？”。左边条件不成立，右边的问题就不用回答了。
② “省一步”
if (年龄 >= 18 && 查看身份证) —— 年龄不够，就不用再查身份证了。
价值 短路不只是“省事”：它能避免错误（如除零）、避免副作用。
注意 短路虽然方便，但不要依赖它来“跳过”重要的操作；条件复杂时，写成清楚的 if 语句更好读、更不容易出错。
逻辑短路求值（二）· 副作用
经典题:执行下面的语句后 b 的值是多少？ 
int a=5, b=6, c=1, x=2, y=3, z=4;
c = (a = c < x) || (b = y > z);
逐步推
① 先算 (a = (c<x)) → (a = (1<2)) → a = 1，括号内为 1（真）；
② || 左边已真 → 短路，右边 (b=y>z) 不执行；
③ 故 b 仍为 6，c = 1。
用逻辑运算表达复杂条件
含义数学写法C 语言正确写法
x 在 [a,b] 内a ≤ x ≤ b(a <= x) && (x <= b)
ch 是英文字母—(ch>='A' && ch<='Z') || (ch>='a' && ch<='z')
典型例题：判断闰年
规则 满足以下任一条件即可：
① 能被 4 整除 且 不能被 100 整除
② 能被 400 整除 
int year = 2024; // 或由 scanf 输入

if ((year % 4 == 0 && year % 100 != 0) 
    || (year % 400 == 0)) {
    printf("是闰年\n");
}
规则要素C 代码对应
能被 4 整除year % 4 == 0
不能被 100 整除year % 100 != 0
条件①（同时满足）用 && 连接前两项
能被 400 整除year % 400 == 0
条件②（或者）用 || 连接条件①和②
铁律 数学里的连续不等式在 C 中必须拆开用 && 连接；
任何“多个条件同时成立”用 &&，“任一成立”用 ||。别忘了加括号！
常见错误（一）：关系与逻辑
❌ 陷阱1：= 与 ==
if (x = 5) {…}
// 这是赋值，值为 5（真），永远执行！
✅ 正确写法
if (x == 5) {…}
// 比较是否相等。建议写 5 == x 防笔误。
❌ 陷阱2：连续不等式
if (3 > 2 > 1) {…} // 算成 (3>2)=1, 1>1=0
✅ 正确写法
if (3 > 2 && 2 > 1){…} // 用 && ，结果真。
❌ 陷阱3：实数直接判等
float f=0.1;
if (f == 0.1) {…}
二进制无法精确表示 0.1，相等判断可能恒为假。
✅ 正确写法
① 误差：if (fabs(f-0.1) <= 1e-8){…}
② 放大转整数比较：
int k = (int)(f*100 + 0.5);
if (k == 10) {…}
（把 0.1 放大 100 倍成 10 再比，彻底避开小数误差）。
课堂练习 · 关系与逻辑
1. 设 int a=3,b=4; 表达式 (a<b) && (a+b>=7) 的值是？
提示：先分别算两个子表达式。
参考答案：a<b 为 1；a+b=7，7>=7 为 1；1 && 1 = 1（真）。
2. 判断下面能否正确表达“x 是 0 到 100 之间的整数”： 0 <= x <= 100
提示：回忆连续不等式规则。
参考答案：不能。应写为 (x >= 0) && (x <= 100)。
3. 若 a=1,b=2；执行x = a>b && (b=5); 后 b 是多少？为什么？
提示：短路求值。
参考答案：b 仍为 2。因为 a>b 为假，&& 短路，(b=5) 不执行。

直接操作二进制位：& 　|　 ^ 　~　 <<　 >>
为什么需要6 个运算符逐位演算典型应用常见陷阱
为什么需要位运算？
核心问题 计算机底层只认识 0 和 1。C 贴近硬件，提供直接对二进制位(bit)操作的运算符，能高效完成普通算术难以表达的事。

🎯典型场景

① 用位标志压缩存储多个布尔状态（权限、开关）；
② 操作硬件寄存器/网络协议/像素；
③ 加密、压缩、哈希的底层基石；
④ 用位移替代乘除法更快。

🔘比喻

关系是“比较”，逻辑是“判断”，位运算是“逐位雕刻”——像一面有很多开关的面板，你能精确拨动任意一个。

典型应用（一）：位的 置1 / 清0 / 翻转 / 测试
核心思路 1 << k 是第 k 位的“单点掩码”：只有第 k 位是 1，其余位全 0。用它和 x 做位运算，就能精确操作第 k 位。 
// ① 将第 k 位置 1
x |= (1 << k);

// ② 将第 k 位清 0
x &= ~(1 << k);

// ③ 翻转第 k 位
x ^= (1 << k);

// ④ 测试第 k 位是否为 1
if (x & (1 << k)) { /* 为 1 */ }

// ⑤ 判断 n 是否为奇数
if (n & 1) { /* 奇数 */ }
① 置 1 x |= (1 << k)
或上 1 → 该位变 1，其余位不变。
② 清 0 x &= ~(1 << k)
与上 0 → 该位变 0，其余位不变。
③ 翻转 x ^= (1 << k)
异或 1 → 该位取反，其余位不变。
④ 测试 x & (1 << k)
与上 1 → 结果非 0 说明该位是 1。
口诀 或上它 → 置 1；与上它的反 → 清 0；异或它 → 翻转；与上它 → 测试。 1 << k 始终是那个“单点掩码”。
典型应用（二）：异或交换两个整数
核心思路 利用异或的自反性：a ^ a → 0、a ^ 0 → a、a ^ b ^ b → a(三次异或，就能让 a、b 互换) 
int a = 3, b = 5;

a = a ^ b;   // a = 3^5 = 6
b = a ^ b;   // b = 6^5 = 3
a = a ^ b;   // a = 6^3 = 5

// 交换后：a = 5, b = 3
为什么对
第二步 b = a ^ b 里的 a 已经是 3^5，所以
b = (3^5)^5 = 3；
第三步同理还原出 5。
注意 当 a、b 指向同一变量时，a ^ a = 0 会把值清零；
工程上更推荐用临时变量交换，可读性更好。int a, b, t; t = a; a = b; b = t;
典型应用（三）：用位运算压缩状态标志
核心思路 一个 char 有 8 位，可以当作 8 个独立开关使用：每一位代表一个状态，用置位/清位/测试来操作。这里用 3 位记录灯、门、窗。 
char flags = 0;   // 0000 0000

// 点亮灯：位 0 置 1
flags |= (1 << 0);   // 0000 0001

// 测试门：位 1 是否为 1
if (flags & (1 << 1)) {
    printf("door open\n");
}

// 关闭窗：位 2 清 0
flags &= ~(1 << 2);   // 位 2 变 0
位210含义
初始000全关
点亮灯001窗关、门关、灯亮
测试门001位 1 是 0，门未开
关闭窗001位 2 本来就是 0
对照 位 0 = 灯，位 1 = 门，位 2 = 窗；
flags |= (1<<k) 置 1，
flags &= ~(1<<k) 清 0，
flags & (1<<k) 测试。
价值 一个字节即可存 8 个布尔状态，省内存、判断快——这是嵌入式与系统程序里压缩状态标志的常见手法。
常见错误（二）：位运算
❌ 陷阱1：位运算 vs 逻辑运算
把 & 、^、 | 写成 &&、 || ——结果类型不同（整数 vs 0/1），且位运算无短路。
✅ 区分
逐位比较/组合用 &、 |、 ^；
整体真假判断才用 && 、||。
❌ 陷阱2：移位越界
对 int 做 x << 40 → 结果未定义。
❌ 陷阱3：~ 与 !
~5 = -6（位取反）；!5 = 0（逻辑非）。两者完全不同。
❌ 陷阱4：对浮点位运算
float/double 不能做位运算 —— 编译报错。
课堂练习 · 位运算
说明 先自己算，再点“显示答案”核对。三题分别练：按位与/或/异或、置位掩码、左移。
1. 6 & 3、6 | 3、6 ^ 3 各是多少？
提示：6 = 0110，3 = 0011，逐位对照规则。
参考答案：6 & 3 → 2，6 | 3 → 7，6 ^ 3 → 5。
2. 把整数 x 的第 3 位（从 0 计）置 1，写出语句。
提示：置位用“或上单点掩码”，第 k 位的掩码是 1 << k。
参考答案：x |= (1 << 3);
3. 5 << 2 等于多少？它在算术上等价于什么？
提示：左移 n 位相当于乘 2ⁿ。
参考答案：5<<2 = 20，等价于 5 × 2² = 5 × 4。
