为什么需要循环：100 个数，要写 100 行
顺序写法输入 100 个数求和
/* 先声明 a1 到 a100，共 100 个变量 */
scanf("%d", &a1);    // 第 1 个
scanf("%d", &a2);    // 第 2 个
scanf("%d", &a3);    // 第 3 个
/* …… 中间还要写 97 行 */
scanf("%d", &a100);   // 第 100 个
s = a1 + a2 + a3 + … + a100;
① 繁琐100 行复制粘贴，极易抄错。
② 难改改成 200 个？整段重写。
③ 死局个数由用户定，根本没法写。
症结这 100 行一模一样，只是数据在变。重复的事应该交给循环——下面压成 6 行。
写循环，先想清四件事

1. 从哪儿开始？

准备初值：i = 1

2. 什么条件继续？

判断条件：i <= 100

3. 每轮做什么？

执行循环体：s = s + i

4. 怎么走向结束？

推进变量：i = i + 1

口诀准备初值、判断条件、执行循环体、推进变量——缺一个，循环就不可能对。
最容易漏漏了推进，条件永远成立，程序就卡死在那儿。
while 的语法格式与 N-S 盒图
格式
while ( 表达式 )
    内嵌语句;
示例
int i = 1, s = 0;
while (i <= 100) {
    s = s + i;
    i++;
}
执行过程
  • 计算 while 后表达式的值，非 0 即“真”、0 即“假”。
  • 非 0 → 执行循环体，并转回表达式重新判断
  • 0 → 结束 while 语句，执行下一条
三条规矩
① 循环体有多条语句时必须用 { } 括成复合语句。
② while (n) 与 while (n != 0) 等价。
③ 循环体中必须有让条件趋向于假的语句。
while 怎么执行：先准备，再判断，后执行
代码对照
// ① 准备（循环前）
int i = 1, s = 0; 

while (i <= 100) {  // ② 判断
    s = s + i;    // ③ 执行（循环体）
    i = i + 1;    // ④ 推进
}                 // 回到 ②
执行过程

1. 准备初值

进入循环前，必须给变量赋好初值（如 i=1, s=0）

2. 判断条件

算括号里的值：为 0 → 结束整个循环

3. 执行循环体

非 0 时，执行花括号内的所有语句

4. 推进变量

执行完后，回到第 2 步重新判断

核心逻辑非 0 就是真，0 才是假。因此 while (1) 是死循环，而 漏写推进也会死循环。
while 和 if 只差一个字，差在哪

if 为真进一次

int i = 1;
if (i <= 100) {
    printf("%d ", i);
    i++;
}
输出：1

while 为真反复进

int i = 1;
while (i <= 100) {
    printf("%d ", i);
    i++;
}
输出：1 2 3 … 100
一句话if 只问一次"要不要做"；while 每做完一遍，都要回来再问一次。
次数确定（一）：1+2+…+100
/* 求 1+2+…+100 */
#include <stdio.h>
int main() {
  int i = 1;      // 循环变量
  int s = 0;      // 累加器
  while (i <= 100) {
    s = s + i;
    i = i + 1;
  }
  printf("s = %d\n", s);
  return 0;
}
输出：s = 5050
为什么拿这道题讲循环？
人类直觉(1 + 100) × 100 ÷ 2 = 5050。利用等差数列公式，人类一步到位。
计算机笨办法不会背公式，只能老老实实加 100 次。
公式解决最规整的一个一旦变形，公式彻底失效，只能靠循环死算：
① 阶乘型：1! + 2! + 3! + ... + n! ② 分数型：1/1 + 1/2 + 1/3 + ...
手工跟踪与边界：差一个就是错
跟着跑一遍
轮次is说明
第 1 轮11加 1
第 2 轮23加 2
…………
第 100 轮1005050加 100
第 101 次1015050只有判断
边界试一遍
条件次数结果 s
i <= 1001005050 ✔
i < 1011005050 ✔
i <= 99994950 错
i != 101100危险
注意边界循环体执行 100 次，条件算了 101 次——最后那次只有判断，没有执行。写边界要考虑：最后一个数满足条件吗？
次数确定（二）：同一种套路，求 n!
/* 求 n! = 1×2×…×n */
int i = 1, n;
long long t = 1;   // 累乘器
scanf("%d", &n);
while (i <= n) {
    t = t * i;
    i++;
}
printf("%lld\n", t);
溢出int 只能装到 12!，求 13! 必须用 long long。
初值不能错累加器是置 0，累乘器是置 1。套路一模一样，只换了初值和运算。
次数不定（一）：算到足够精确为止
问题利用公式 π/4 = 1 - 1/3 + 1/5 - 1/7 + ... 求 π 的近似值，直到最后一项绝对值 < 10-6 为止。
double term = 1.0;       // 当前项
double pi = 0;
double denominator = 1.0;// 分母
int sign = 1;             // 符号 (+1/-1)

while (fabs(term) >= 1e-6) {
    pi = pi + term;       // 累加
    denominator += 2;     // 分母+2
    sign = -sign;         // 变号
    term = sign / denominator; // 下一项
}
pi = pi * 4;
遇到“次数不定”怎么思考？
1️⃣ 找停止条件：题目中的“直到...为止”或要求的精度。
2️⃣ 翻译成 while：把“直到...为止”翻译成 while(继续做)。
3️⃣ 提前算出判断量：在循环体末尾，必须算出下一轮用来判断的变量。
次数不定：不知道输入几个数据怎么办？
一、有特定结束标志（哨兵控制）
题目规定某个特殊值（如 -1）代表结束。
int score, sum = 0, count = 0;
scanf("%d", &score);     // 先读第一个
while (score != -1) {    // -1 是结束标志
    sum += score;
    count++;
    scanf("%d", &score);  // 再读下一数
}
特点逻辑简单，但必须规定该数值不能是合法的业务数据（如 0 是合法数，不能用 0 当结束符）。
二、无特定结束标志（EOF 控制）
任何值都可能出现只能靠“读不动”来停。
int x, sum = 0, count = 0;
while (scanf("%d", &x) == 1) {
    sum += x;
    count++;
}
关键scanf 成功读入数据返回 1，遇到非法字符（如字母）或按 Ctrl+Z 则返回 0 或 EOF，循环自然结束。
进阶探讨：求最大值
任务输入任意个整数（遇到非数字时输入结束），求其中的最大值。

❌ 写法 1：初值设 0

int x, max = 0;
while (scanf("%d", &x) == 1) {
    if (x > max) 
        max = x;
}
printf("Max=%d\n", max);
缺陷若输入全是负数（如 -5 -10 -3），程序会输出 0，因为 0 > 任何负数。

✅ 写法 2：计数器记录首个元素

int x, max, count = 0;
while (scanf("%d", &x) == 1) {
    if (count == 0) max = x;
    else if (x > max) max = x;
    count++;
}
if (count > 0) 
    printf("Max=%d\n", max);
巧妙用 count 判断，把读到的第一个数直接定为 max 基准。
进阶写法： while(1) + break
思考在不知道循环次数时，把读取条件和退出逻辑全塞进 while() 里，往往会让条件变得很长。有没有更符合人类思维“先做，不行再退”的写法？
int x, max, count = 0;

while (1) { // 条件永远为真，先进入
    if (scanf("%d", &x) != 1) 
        break; // 读不到数据，打破循环
        
    if (count == 0) max = x;
    else if (x > max) max = x;
    count++;
}

if (count > 0) 
    printf("Max=%d\n", max);
优点将“获取数据”和“判断是否结束”拆成了两步，逻辑极其清晰：读不到？那就 break！
更适用的场景如果读取数据的逻辑很长，此时把所有条件塞进 while() 括号里会极其臃肿。这时用 while(1) 配合 break 是最佳实践。
补充说明下一章要学的 do-while 语句，本质上就是 while(1) + break 的标准语法糖。
次数不定（三）：不知道要读几个字符
读到这一行结束
int c;
while ((c = getchar()) != '\n')
    putchar(c);          // 原样输出
解释先读一个字符存进 c，再拿它跟回车比；不等于回车就执行循环体。
读到整个输入结束
int c;
while ((c = getchar()) != EOF)
    putchar(c);          // 原样输出
怎么结束Windows 按 Ctrl + Z 再回车；Linux / Mac 按 Ctrl + D。
⚠️ 能把 getchar() 换成 scanf("%c", &c) 吗？
不能简单替换。如果用 while (scanf("%c", &c) != '\n') 会直接陷入死循环。
原因是：scanf 的返回值不是读到的字符，而是成功读入的数据个数。只要读到了字符（哪怕是回车），它就返回 1。判断条件变成了 1 != '\n'，永远成立。
多个字符处理：边读边改（加密）
核心逻辑读一个字符、偏移、输出，再读下一个。不需要把所有字符存进数组。
int c;
while ((c = getchar()) != '\n') {
    if (c >= 'a' && c <= 'z')
        c = (c - 'a' + 3) % 26 + 'a';
    else if (c >= 'A' && c <= 'Z')
        c = (c - 'A' + 3) % 26 + 'A';
    putchar(c); // 边读、边改、边输出
}
原理每个字母向后移 3 位（如 a→d, z→c），非字母不变。取模运算保证字母在 a~z 中循环。
多个字符处理：凯撒密码的解密
回顾加密是把字母向后移 3 位，解密就是把它向前移 3 位。核心代码几乎一样。
int c;
while ((c = getchar()) != '\n') {
    if (c >= 'a' && c <= 'z')
        // 注意这里：-3 之后 +26
        c = (c - 'a' - 3 + 26) % 26 + 'a';
    else if (c >= 'A' && c <= 'Z')
        c = (c - 'A' - 3 + 26) % 26 + 'A';
    putchar(c);
}
为什么要加 26？在 C 语言中，负数取模还是负数。比如字母 'a'，偏移量是 0，0 - 3 = -3。-3 % 26 的结果仍是 -3，并没有循环到 'x'。在取模前先加上 26 就能补救。
运行演示密文: Khoor → 解密: Hello
多个字符处理：边读边改（加密二）
场景按位异或（XOR）加密。这是一种更通用、更安全的单字符加密方式。将每个字符与一个密钥字符（如 'K'）进行异或。
int c;
while ((c = getchar()) != '\n') {
    // 异或的特性：A ^ K = B, B ^ K = A
    c = c ^ 'K'; 
    putchar(c); // 输出乱码即加密成功
}
异或的妙用加密和解密使用同一个密钥。你用 'K' 加密得到乱码，再用 'K' 异或，又能还原成明文。
运行演示输入: C Language → 输出: )#6HXJYJXH
多个字符（三）：边读边改，边读边输出
例：去掉所有空格（压缩输出）
int c;
while ((c = getchar()) != '\n')
    if (c != ' ')
        putchar(c);
思路读一个、判一个，不合意就不输出。
例：小写转大写（改完再输出）
int c;
while ((c = getchar()) != '\n')
    if (c >= 'a' && c <= 'z')
        putchar(c - 32);   // 小写转大写
    else
        putchar(c);
32 是怎么来的'a' 是 97，'A' 是 65，正好差 32——小写减 32 就是大写。
错误一：多写一个分号，循环体就没了
错误写法while (i <= 100);　这个分号让循环体变成了一条空语句

❌ 错：分号结尾

while (i <= 100);
{
    s = s + i;
    i++;
}
结果：卡死（i 永不变）

✅ 对：不要分号

while (i <= 100)
{
    s = s + i;
    i++;
}
结果：s = 5050
怎么发现程序不输出、像卡住了，第一反应就查 while 那行结尾有没有多余分号。
错误二：忘了让循环变量往前走

❌ 错误写法

int i = 1, s = 0;
while (i <= 100) {
    s = s + i;   // i 一直是 1
}                // 少了 i++

循环体里只有累加，没有 i++。

自查口诀沿循环体走一遍，确认循环变量真的在变。
现象屏幕上什么都没出来，程序却一直不结束——它正在疯狂重复同一件事。
现场处理控制台按 Ctrl + C 强行终止，别等着。
错误三：累加器忘了清零

✗ 错：不赋初值

int s;       // 里面是什么？
int i = 1;
while (i <= 100) {
    s = s + i;
    i++;
}

✓ 对：先给一个干净的 0

int s = 0;   // 明确从 0 开始
int i = 1;
while (i <= 100) {
    s = s + i;
    i++;
}
为什么每次不一样局部变量不初始化，里面是垃圾值。
规矩累加器写 0，累乘器写 1，计数器写 0。
错误四：用浮点数判断"相等"
危险写法while (f != 0.0) —— f 可能永远也"不等于"0
原因0.1 在二进制里是无限循环小数，存进 double 就被截断了。
// 危险：可能死循环
while (f != 0.0)
    f = f - 0.1;
// 安全：足够接近 0
while (fabs(f) > 1e-6)
    f = f - 0.1;
规矩浮点数永远不要用 == 或 != 比，要比就比 fabs(a-b) < 1e-6。需要 #include <math.h>。
随堂检测：两道题，当堂推一遍

Q1：执行几次？

int k = 1;
while (k = 1) k--;

A. 1 次　B. 0 次　C. 无数次　D. 语法错误

Q2：i 最后是多少？

int i = 0;
while (i < 5) i++;

A. 4　B. 5　C. 6　D. 不确定

提示Q1 看 = 与 ==：赋值表达式的值是赋进去的那个值，恒为真。Q2 看退出时循环变量已经变了。
答案Q1 选 C（死循环）；Q2 选 B。
