这一讲的重点 上一讲看到「每层栈帧各有各的 n」。这一讲把这句话讲清楚： 名字只在它被定义的那一小块地方算数。
换不过来的两个数
/* 把两个数换个位置 */
void swap(int a, int b)
{
    int t = a;
    a = b;
    b = t;
}
int main(void)
{
    int x = 3, y = 8;
    swap(x, y);
    printf("%d %d\n", x, y);
    return 0;
}
先猜一下 swap 里明明换了，t = a、a = b、b = t 三步一步不缺。 那 main 输出应该是 8 3 吧？
实际输出

没换过来 一个都没动。程序不报错、不警告，就这么安安静静地什么都没干。

什么叫作用域
定义 一个变量能被程序按名字找到的那段代码范围，叫它的作用域。 出了这个范围，名字就不认识了。
  • ① 是空间概念说的是代码里的哪几行能用这个名字，跟时间无关
  • ② 由位置决定变量写在哪一行，决定了它的作用范围有多大，写完就定死
  • ③ 编译器要查编译器按名字找变量，找不到就报 undeclared，程序根本编不过
换个说法 名字能不能用，取决于你站在哪一行。站在 swap 里就看不见 main 的 x， 站在 main 里也看不见 swap 的 a。
局部变量：只在本函数内有效
void f(void)
{
    int k = 1;        /* 局部 */
    printf("%d\n", k);
}
int main(void)
{
    f();
    printf("%d\n", k);  /* 报错 */
    return 0;
}
编译不过 k 是 f 里定义的，main 里没有这个名字，编译器直接报错。
定义 在函数内部（或复合语句内部）定义的变量，叫局部变量。
注意 这不是「权限不够」或者「private」。 是这个变量根本不存在，编译器连它的类型都不知道。 
gcc 报错原文main.c: In function 'main':
main.c:9:20: error: 'k' undeclared (first use in this function)
进函数时分配，出函数时回收
void f(void)
{
    int k = 0;
    k++;
    printf("%d ", k);
}
int main(void)
{
    f();
    f();
    f();
    return 0;
}
输出
1 1 1
为什么不是 1 2 3 不是。k 是局部变量，每调用一次 f 就重新分配一个，仍从 0 开始。 上一次调用里的 k，在函数返回时已经被回收了。
记住这一条 局部变量的存在时间就是这一次函数调用： 调用时分配，返回时回收。三次调用，三个不同的 k。
形参也是局部变量
int add(int a)     /* a 是形参 */
{
    a = a + 100;    /* 改副本 */
    return a;
}
int main(void)
{
    int x = 7;
    printf("%d\n", add(x));
    printf("%d\n", x);
    return 0;
}
输出
107
7
形参的身份 形参是函数自己造出来接值的变量，只是写在参数表里。 它和函数体第一行写一句 int a; 没有区别。
所以 在函数里给形参赋值，只影响这个副本。 想通过改形参把结果带回去，这条路走不通。
花括号也是一道边界
int main(void)
{
    int s = 0;
    {
        int s = 10;   /* 内层 s */
        printf("内层 %d\n", s);
    }
    printf("外层 %d\n", s);
    return 0;
}
输出
内层 10
外层 0
两个 s 里层那对花括号里声明的 s，只管到花括号结束。 出了花括号，这个名字就不再有效，看到的又变回外面的 s。
范围最小的局部 函数的形参、函数体的一对花括号、if / for / while 后面的一对花括号， 每一对都划出一个作用范围。
局部变量没给初值时是几
int g;                /* 全局，没初值 */
int main(void)
{
    int a;            /* 局部，没初值 */
    static int s;     /* 静态，没初值 */
    printf("g = %d\n", g);
    printf("s = %d\n", s);
    printf("a = %d\n", a);
    return 0;
}
局部变量是不定值 这一次跑出来 a = 0，看着挺正常。 但换个机器、改几行代码，它可能是 32764 或者别的数。 它不是 0，只是这次恰好是 0。
全局和静态是 0 g 和 s 没写初值，编译器会把它们清成 0。这一条是标准保证的，可以放心用。
建议 局部变量定义的时候顺手给个初值。这一行能省掉半天的排查。
全局变量：写在所有函数外面
#include <stdio.h>

int total;      /* ① 函数外面 */
int cnt;

void add(int s)  /* ② 从这里起可见 */
{
    total += s;
    cnt++;
}
/* main 里也看得见 */
定义 在函数外面定义的变量，叫全局变量。 它的作用范围是从定义那一行起，到本文件结束。
位置有讲究 全局变量必须写在要用它的函数之前。 写在 main 后面，前面的 add 就看不见它。
习惯 统一写在 #include 之后、第一个函数之前。 一眼就能看出这个程序有哪些共享数据。
全局变量和程序同寿命
比什么局部变量全局变量
写在哪函数或复合语句内部所有函数外面
作用范围从定义处到所在块结束从定义处到本文件结束
存在多久进函数时分配，返回时回收程序启动时分配，程序结束时回收
没给初值不定值自动为 0
谁看得到只有本函数所有函数
最容易记的一条 局部变量每次调用重新分配，全局变量整个程序只有一份。 所以第 8 页那段 f(); f(); f(); 输出的是 1 1 1， 把 k 改成全局就变成 1 2 3 了。
全局变量好用，但代价不小
① 谁都能改 任何一个函数都能动它，出了问题不知道该找谁。 查一个数为什么变成 99，得把所有函数翻一遍。
② 函数不再独立 用了全局变量的函数，换到别的程序里就编不过。 它偷偷依赖了一个外面看不见的东西。
③ 名字容易撞 全局名字多起来，随便起个 i、sum 就可能和别处的重名，然后就遮蔽了。
对照一下 上一讲的递归函数，每层栈帧的 n 都是自己的局部变量，所以互不干扰。 要是把那个 n 写成全局变量，五层调用共用一个 n， 压到最里面的时候 n 已经变成 1，外面那些层全乱。
记住这一条 能用参数传的，就别用全局变量。参数写在函数头上，谁给了什么一目了然。
一个提醒 全局变量一多，函数之间就靠这些变量暗中联系。读代码时得同时记住好几个名字当前的值， 可这些值在任何一次函数调用里都可能被改掉。
什么时候该用全局变量
判断什么情况举例
✓多个函数共享同一份数据统计总人数、计数器
✓常量，定义一次到处用，谁也不改它数组长度、圆周率
✗只是想把一个结果从函数里带出来用返回值就够了
✗图省事，少写几个参数改成参数传递更清楚
✗几个函数各算各的中间结果各用各的局部变量
判断办法 看一条：这个数据在整个程序里是否只有一份？是，比如全班人数，才考虑全局； 不是，比如这次调用算出的中间结果，就放在局部变量里。
拿总分试一试 确认全局只有一份时才用它。两个班同时统计，一个 total 就把数据混在一起了。
同名的时候，用哪一个
全局 n = 10
main 函数 n = 20
花括号里 n = 30
三处 n，其实是三个不同的变量
同名遮蔽 内层定义的变量和外层同名，就把外层遮住了，叫同名遮蔽。 遮住的只是名字，外层那个变量的值一点没变。
怎么判断用哪个 看这一行站在第几层，就先用哪一层的 n。由内往外一层层找，找到第一个就停。
花括号一结束 遮挡消失，外面的 n 原样露出来，值还是 20。
一段代码，三个 n
int n = 100;        /* 全局 n */
void f(void)
{
    int n = 5;      /* 局部 n */
    printf("f   : %d\n", n);
}
int main(void)
{
    printf("main: %d\n", n);
    f();
    printf("back: %d\n", n);
    return 0;
}
输出
main: 100
f   : 5
back: 100
这一行在哪用的是哪个 n
main 第一句全局的 100
f 里面那句f 自己的 5
main 最后一句还是全局的 100
看清一点 f 里那个 n 从头到尾没碰到全局的 n，回来以后全局还是 100。
想改全局，却改了自己的
int count = 0;      /* 全局计数 */
void tick(void)
{
    int count = 0;  /* 多写这行 */
    count++;
}
int main(void)
{
    tick(); tick(); tick();
    printf("%d\n", count);
    return 0;
}
输出
0
错在哪 tick 里那一行 int count = 0; 造了一个新的局部变量， 把全局的 count 挡住了。加了三趟，加的全是这一个临时的副本， 函数一返回就没了。
规范写法 要用全局那个，就别在函数里再定义同名变量。 直接把那一行删掉，count++ 加的就是全局的。
编译器是怎么找名字的
1这一对花括号

2外面一层块
没有就退到外面那对花括号，一层层往外
3函数外的全局

4都没有
报 undeclared，程序编不过
规则就一句 由内往外，找到就停。找到第一个同名的就用它，不再往外找。
拿第 17 页的图对一遍 站在最里层输出 n，第一层就找到 30，不再往外找； 跨出这对花括号，才轮到 main 的 20。
排查办法 遇到「明明赋了值怎么没变」，先数一遍同名的变量有几个， 再看你那一行站在第几层。
变量到底存在哪块内存
内存布局（示意）上边地址高，下边低
栈区
局部变量、形参。进函数才分配，返回就收回。
栈从高地址往低地址长：每调用一个函数，就往下压入一块。
a 0061FE4C
堆区
由 malloc、calloc 这类函数动态申请的内存，
用完要自己释放。第 6 章再讲。
静态区
全局变量、static 变量。程序一启动就划好，
存在到程序结束，没给初值就是 0。
g 00407970s 00407030
代码区
编译好的机器指令，只读，程序运行期间一直在这儿。
把这三个变量的地址输出来看看
/* 在一台机器上实跑 */
&g = 00407970   /* 全局 */

三组地址不在一处 全局和 static 都在 0040 段，局部在 0061 段，确实分属不同的区域。
数字不用记 每台机器、每次运行都不一样。只要知道局部在栈区，全局和 static 在静态区。

作用域和生存期，两个问题
说法问的是什么举例
作用域代码里哪几行能用这个名字f 里的 k，出了 f 就找不到
生存期内存什么时候分配、什么时候回收static 的 k 在 f 返回后仍然存在
一个说地方，一个说时间 作用域说的是空间，名字在代码哪个范围有效；生存期说的是时间，变量在内存里存在多久。 这两件事可以不一致：static 局部变量出了 f 谁也用不了，可它的内存一直都在。
这讲的重点 写函数时先问一句「这个名字在哪儿能用」，这就是作用域，本讲前面三节都在说这件事。 生存期记住一条：局部变量出了函数就没了，只有加了 static 才留到程序结束（第 21 页）。
同一件事，两种写法
版本一 · 靠全局变量
int total;         /* 全局 */
void add(int s)
{
    total += s;
}
int main(void)
{
    total = 0;
    add(78); add(85); add(92);
    printf("%d\n", total);
    return 0;
}
版本二 · 靠参数传递
int add(int t, int s)
{
    return t + s;
}
int main(void)
{
    int t = 0;
    t = add(t, 78);
    t = add(t, 85);
    t = add(t, 92);
    printf("%d\n", t);
    return 0;
}

比什么版本一 · 全局变量版本二 · 参数传递

函数程序举例：三个函数拼起来
int fix(int s)      /* 修正 */
{
    if (s > 100) s = 100;
    if (s < 0)   s = 0;
    return s;
}
int total(int a, int b, int c)
{
    return a + b + c;
}
int main(void)
{
    int s1, s2, s3;
    scanf("%d%d%d", &s1, &s2, &s3);
    s1 = fix(s1);
    s2 = fix(s2);
    s3 = fix(s3);
    printf("%d\n", total(s1,s2,s3)/3);
    return 0;
}
看变量都住哪 fix 里的 s、total 里的 a b c、main 里的 s1 s2 s3，全是各自的局部变量。 三组人各干各的，靠参数交接，谁也不碰谁的东西。 输入 120 85 -5，结果是 61 （120 修成 100，-5 修成 0，(100+85+0)/3 = 61）。
五个常见错误
#错在哪为什么怎么办
①指望函数改掉实参形参是副本，改不回去用返回值带出来
②函数里又定义同名变量遮蔽了，改的是局部那个删掉重复定义
③局部变量没给初值就用值不定，不是 0定义时顺手赋值
④全局变量写在函数后面前面读不到这个名字统一写在最前面
⑤返回后还想用局部变量那块内存已经回收了返回前把值交出去
第 ④ 条的真报错 error: 'total' undeclared，读到那一行时还没见过这个名字。 C 语言从前往后扫，只认已经出现过的东西。
第 ⑤ 条 等学完指针会见到「返回指向局部变量的指针」，编译能过，跑起来结果飘忽。
随堂检测
1swap 之后输出什么
swap 里面把 a、b 换了个位置，main 里写 swap(x, y) 之后输出 x、y。
输出是（单选）：
A. 8 3 B. 3 8 C. 0 0 D. 编译错
2三层同名的 a
全局 a 是 10，main 里 a 是 20，花括号里 a 是 30，三处各输出一次。
输出是（单选）：
A. 20 30 10 B. 20 30 20 C. 10 30 10 D. 30 30 30
3static 的 k
f 里把 k 定义成静态局部变量，初值 0，接着 k++ 并输出。main 连调三次 f。
输出是（单选）：
A. 1 1 1 B. 1 2 3 C. 3 3 3 D. 0 0 0
4没给初值的两个变量
一个全局变量 g，一个局部变量 a，都没赋值，现在把它们输出（单选）：
A. 都是 0 B. 都不定 C. g=0，a 不定
答案 1 · swap 之后输出什么
选 B。swap 里换的是形参 a、b，也就是 x、y 的两份副本。副本换成 8、3 之后，函数一返回就被回收，x、y 从头到尾没被碰过。程序不报错，只是白干一趟。
再点一次「看解析」收起来
答案 2 · 三层同名的 a
选 B，输出 20 30 20。第一句站在 main 里，用的是 main 自己的 20；第二句进了花括号，用 30；出来花括号那一层没了，又回到 main 的 20。全局的 10 从头到尾被挡着，一次都没用上。
再点一次「看解析」收起来
答案 3 · static 的 k
选 B，输出 1 2 3。static 让 k 从栈搬到静态区，第一次调用时初始化成 0 之后就再也不重置，三趟调用共用同一个 k，所以一路加上去。没写 static 的话才是 A 的 1 1 1。
再点一次「看解析」收起来
答案 4 · 没给初值的两个变量
选 C。全局变量放在静态区，程序启动时整块清零，所以 g 一定是 0，这一条标准有保证。局部变量在栈上，栈上留着上一次用过的数据，所以 a 是那次残留的值，可能是 0，也可能是别的数。这一讲第 11 页实跑时 a 恰好是 0，但换个环境就不一定。
再点一次「看解析」收起来
本讲小结
  • ① 值传递实参的值抄一份给形参，函数里改的是副本，带不回去
  • ② 局部变量作用范围只在本函数或本块，进函数才分配，返回就回收，初值不定
  • ③ 全局变量从定义处到文件末都能用，存在到程序结束，初值自动为 0
  • ④ 同名遮蔽由内往外找，找到就停；挡住的是名字，不是值
  • ⑤ static 局部作用域不变，生存期变成整个程序，初值只给一次
  • ⑥ 空间与时间作用域看空间，生存期看时间；static 局部这两件事不一致
一句话 一个变量归谁管，看它写在哪一行。写在函数里的只归这个函数， 写在花括号里的只归这对花括号，写在函数外面的才归所有人。
