一道题里两层活儿

求 1! + 2! + 3! + … + 10!。阶乘上一讲已经会算了，现在要把十个加起来。

long fac(int k);   /* 上一讲写过 */

int main()
{
    int i;
    long s = 0;
    for (i = 1; i <= 10; i++)
        s += fac(i);   /* 逐个算 */
    printf("%ld\n", s);
    return 0;
}
4037913
main 只做三件事开一个累加变量 s，循环十次，每次把 fac(i) 加进来。算阶乘的活儿一行都没写。
最底一层，和中间一层
fac：只算阶乘，不喊别人
long fac(int k)
{
    int i;
    long r = 1;
    for (i = 1; i <= k; i++)
        r *= i;
    return r;
}
sum：一边调 fac，一边加
long sum(int n)
{
    int i;
    long s = 0;
    for (i = 1; i <= n; i++)
        s += fac(i);
    return s;
}
三层排下来main 调 sum(10)，sum 调 fac(i)，fac 算出结果。函数在执行过程中又调了另一个函数，就叫嵌套调用。
一句话发起调用的叫主调函数，被叫的叫被调函数。sum 不是 fac 的上级，它只是这一趟的调用者。
走一遍：谁在跑，谁在等
long sum(int n)
{
    int i;  long s = 0;
    for (i = 1; i <= n; i++)
        s += fac(i);
    return s;
}
int main()
{
    printf("%ld\n", sum(10));
    return 0;
}
① main 停调 sum(10)，自己停在第 11 行等结果。
② sum 停进循环，调 fac(1)，停在第 6 行等它交回 1 的阶乘。
③ fac 算完返回 1，格子收回。sum 里 s 变成 1，i 加 1 接着走第二趟。
④ 十趟走完sum 返回 4037913，main 输出，栈空了。
看这一列「谁在等」这一列就是调用栈。同一时刻只有一个函数在跑，其余都在等它的结果。
声明为什么一定要写在前面
✗ 定义写在 main 后面，又没有声明
int main()
{
    printf("%ld\n", sum(10));
    return 0;
}
long sum(int n) { … }
✓ 声明放最前面
long sum(int n);
int main()
{
    printf("%ld\n", sum(10));
    return 0;
}
long sum(int n) { … }
左边那段去编译warning: implicit declaration of function 'sum'
error: conflicting types for 'sum'
为什么编译器从头往后扫，读到 sum(10) 时还没见过它，只好先按「返回 int」猜一个；可后面真的定义是 long，两下对不上。
声明只写样子函数头加一个分号，没有函数体，不生成代码，只是提前说明一下。
一道绕人的年龄题
题目五个人坐成一排。问第 5 个人多大，他说：我比第 4 个人大 2 岁。问第 4 个，他说比第 3 个大 2 岁……问第 1 个，他说我 10 岁。第 5 个人多大？
只能这么问想知道第 5 个，得先知道第 4 个；想知道第 4 个，得先知道第 3 个。一路问下去，问到第 1 个，答案才出来。
五句话一模一样「比前一个人大 2 岁」，只换了编号。同一件事做四遍。
这就是递归要解决的问题，可以写成「同样的问题，规模小一号」。一直小到不用再问为止。
顺着往下问
age(5) = age(4) + 2
age(4) = age(3) + 2
age(3) = age(2) + 2
age(2) = age(1) + 2
age(1) = 10   /* 停 */
问了四层，一个数都没算出来每一层都在等下一层的答案。
最后一行不一样age(1) = 10 不用再问任何人。这一行叫出口，也叫终止条件。
然后往回算12、14、16、18，一步一个，四步就回来了。
写成函数
int age(int n)
{
    int c;
    if (n == 1)
        c = 10;      /* 出口 */
    else
        c = age(n - 1) + 2;
    return c;
}
18
main 里怎么用printf("%d\n", age(5)); 一句就够，跟调普通函数一样。
两行各管一件事if 管「什么时候停」，else 管「没停的时候，把问题换成小一号的自己」。
递归的两条硬条件
① 自己调自己函数体里出现自己的名字，把问题缩成小一号的同款问题。
② 有出口某个条件下不再调用自己，直接给出答案。
少第一条没有自己调自己，那就只是一个普通函数，跟递归没关系。
少第二条程序一直往下调，直到把内存里的栈用光，然后崩溃。这叫栈溢出。
先想哪一条先想出口。出口写对了，剩下的只是把大问题写成小一号的自己。
少一条会怎样
/* 出口那一行被删了 */
int age(int n)
{
    return age(n - 1) + 2;
}
age(5) → age(4) → … 一路往下，停不下来 程序崩溃：stack overflow
为什么是崩溃，不是死循环循环占的地方始终是那几个变量，递归不是。每调一次，系统要在栈上开一格存现场。格子只加不减，栈满了就崩。
编译器不管这事语法完全正确，编译能过，跑起来才炸。只能靠写之前想清楚出口来避免。
现场怎么认程序刚跑就退出，一个字都没输出，或者弹出「已停止工作」。先回头找出口。
n! 的递归定义
n! = 1           当 n ≤ 1
n! = n × (n−1)!  当 n > 1
long fact(int n)
{
    if (n <= 1) return 1; /* 出口 */
    return n * fact(n - 1);
}
一行对一行第一行是出口，第二行是自己调自己。代码几乎是照着抄下来的。
两个词递推：往下走，把待算的式子挂起来。
回归：碰到出口往回走，一层层把值代进去。
自己展开一遍fact(4) = 4 × fact(3)
　　　 = 4 × (3 × fact(2))
　　　 = 4 × (3 × (2 × 1)) = 24
为什么用 <= 不用 ==数学上 0! = 1。出口写成 n <= 1，把 0 一并挡住；只写 n == 1 的话，传 0 进来会一路减到负数，栈越压越深。
fact(4)：压进去，再弹回来
long fact(int n)
{
    if (n <= 1) return 1;
    return n * fact(n - 1);
}
① 往下压：四层，谁也没算出结果
第 4 层fact(4)　n = 4，挂着 4 * fact(3)，等
第 3 层fact(3)　n = 3，挂着 3 * fact(2)，等
第 2 层fact(2)　n = 2，挂着 2 * fact(1)，等
第 1 层fact(1)　n = 1，走出口，直接返回 1。触底了。
② 往回弹：一层一个结果
回 fact(2)2 × 1 = 2　→　回 fact(3)：3 × 2 = 6　→　回 fact(4)：4 × 6 = 24
进 fact(4) 进 fact(3) 进 fact(2) 进 fact(1) 触底，返回 1 回 fact(2) = 2 回 fact(3) = 6 回 fact(4) = 24
看出规律前四行连着四个「进」，一个结果都没有；后面四个「回」，一层一个。压在栈里的四层是同时存在的。
容易想错不是「n 减到 1 就乘 1」，每层乘的是自己那个 n：4 × 3 × 2 × 1。
回头看一眼：递归算不算嵌套

讲到这里，可以把递归和前面那种嵌套调用摆在一起比一比了。

  • 谁在调谁嵌套：调的是别的函数
    递归：函数体里出现自己的名字
  • 走到头以后嵌套：一层层剖下去，干完就结束
    递归：触底后沿原路一层层返回来
  • 停得下来吗嵌套：不会，链条是有限的
    递归：会，出口写错就永远停不下来
  • 本讲例子嵌套：main → sum(10) → fac(i)
    递归：fact(4) → fact(3) → fact(2)
嵌套：调的是别人
/* sum 里这一句 */
s += fac(i);
递归：调的是自己
/* fact 里这一句 */
return n * fact(n - 1);
结论递归也是嵌套调用，特殊在调用者和被调用者是同一个函数。前面讲的「谁在跑、谁在等」原样适用。
递归和循环，怎么选

同一道阶乘题，两种写法都能做。差别在这几处：

  • 代码长度循环：要自己维护计数器、累加变量
    递归：通常更短，跟数学式子接近
  • 读起来循环：一步一步走，踏实
    递归：想通结构就一眼，想不通就绕
  • 运行开销循环：小，几个变量而已
    递归：大，每层都要开一个栈帧
  • 最大隐患循环：边界写错，多跑或少跑一次
    递归：出口写错，栈溢出
  • 什么时候用循环：次数明确，能从头数到尾
    递归：问题本身就是一层套一层
记住这一条能用循环顺手写出来的，就用循环。递归留给那些用循环写会别扭的题。
什么样的题适合递归

拿到一道题，先问自己三句。三句都答得上来，这题就适合递归。

① 能不能写成「自己 + 小一号的自己」n! 写成 n × (n−1)!，二进制写成「先转 n/2，再输出 n%2」。写不出来，递归就无从下手。
② 有没有天然的最小情形1! = 1、n 只剩一位数、盘子只剩一个。有这个最小情形，才停得下来。
③ 每次是不是真的变小了n−1、n/2 都会变小。写成 fact(n) 里调 fact(n)，永远不缩小，等于没出口。
三问都过这题就可以用递归。少一条，先回头把条件补上，别急着写代码。
输出写在递归前，还是后

两段代码只差 printf 的位置，输出顺序整个翻过来。先看倒着输出的：

void f(int n)
{
    if (n == 0) return;
    printf("%d ", n);  /* 先输出 */
    f(n - 1);
}
4 3 2 1
先输出往下压时输出，压到哪层就先输出哪层的 n，所以是倒序。

把 printf 挪到递归调用后面，结果就正过来了：

void g(int n)
{
    if (n == 0) return;
    g(n - 1);
    printf("%d ", n);  /* 后输出 */
}
1 2 3 4
后输出弹回来时输出，最底下的先弹，所以是正序。
后面两节都要用printf 挪一行，输出顺序就反过来。看递归题先分清一件事：这一句是往下时做，还是回来时做。
走一遍：4321 和 1234 从哪来

同一个 4，只把 printf 挪一行，输出顺序就反过来。

void f(int n)
{
    if (n == 0) return;
    printf("%d ", n);   /* 先输出 */
    f(n - 1);
}
int main() { f(4); return 0; }
① 往下压：压一层输出一个
main调 f(4)，把 4 交进去
f(4)不触底，先输出 4，再调 f(3)
f(3) f(2) f(1)每层都一样：先输出自己那个 n，再往下。四层压满，输出已经是 4 3 2 1
f(0)n = 0 触底，直接 return，什么都不输出
② 往回弹：这一版回来时不再输出
main 调 f(4) 输出 4 输出 3 输出 2 输出 1 进 f(0) f(0) 返回 f(1) 返回 f(2) 返回 f(3) 返回 f(4) 返回
看出规律输出集中在前四步，全在往下压的时候；回来那五步一声不响。
③ 把 printf 挪到调用后面
void g(int n)
{
    if (n == 0) return;
    g(n - 1);           /* 先递归 */
    printf("%d ", n);   /* 后输出 */
}
int main() { g(4); return 0; }
g(4)一路压到 g(0) 才开始输出，回来时依次输出 1、2、3、4。压进去的顺序是 4 3 2 1，弹出来的顺序是 1 2 3 4
一句话printf 写在调用前是倒序，写在调用后是正序。两版代码只差一行。
十进制转二进制

这道题正好试一下「回来时做」。先看循环版：

循环版：得自己找最高位
void toBinLoop(int n)
{
    int p = 1;
    while (p * 2 <= n) p *= 2;
    while (p > 0) {
        printf("%d", n / p % 2);
        p /= 2;
    }
}
拿 13 走一遍，先除再对 2 取余
p = 8　13/8=1 → 1
p = 4　13/4=3 → 1
p = 2　13/2=6 → 0
p = 1　13/1=13 → 1
为什么多一段循环从低位往高位算，可输出却要先给高位。只好先算出最高位，再倒着往下取。
递归版：栈替你排好队
void toBin(int n)
{
    if (n == 0) return;
    toBin(n / 2);      /* 先转高位 */
    printf("%d", n % 2);
}
toBin(13) → 1101
好在哪不用找最高位。每层的 n 存在自己栈帧里，弹回来正好从高位输出到低位。

这是两套方案，别把两份函数和两个 main 放进同一个文件。传 13 进去，两版都输出 1101。

走一遍：toBin(13) 为什么输出 1101
void toBin(int n)
{
    if (n == 0) return;
    toBin(n / 2);    /* 先转高位 */
    printf("%d", n % 2);
}
int main() { toBin(13); return 0; }
① 往下压：四层，一位都没输出
toBin(13)13 ÷ 2 得 6，先调 toBin(6)，自己不输出
toBin(6)6 ÷ 2 得 3，继续往下
toBin(3)3 ÷ 2 得 1，还剩最后一层
toBin(0)1 ÷ 2 得 0，触底，return
② 往回弹：一层输出一位，先出来的是最高位
进 toBin(13) 进 toBin(6) 进 toBin(3) 进 toBin(1) 进 toBin(0) toBin(0) 返回 输出 1 输出 1 输出 0 输出 1
连起来1 1 0 1，正是 13 的二进制。第一层 toBin(13) 算的是 13 % 2 = 1，它最后才输出，却正好是最低位。
输出整数的每一位

同一套走法换个数字：把 1234 正着输出，每位之间空一格。

void pr(int n)
{
    if (n < 10) {
        printf("%d ", n);  /* 一位 */
        return;
    }
    pr(n / 10);        /* 高位 */
    printf("%d ", n % 10); /* 末位 */
}
pr(1234) → 1 2 3 4
为什么先递归1234 的末位是 4，可题目要先输出 1。把 1234、123、12 一路压下去，弹回来时自然从 1 开始。
对比一下循环要从头输出，得先算出有几位、再一位一位取高位，比这里多绕一段。这条正是上一节那个「往下做还是回来做」的用处。
走一遍：pr(1234) 每一位怎么排好队
void pr(int n)
{
    if (n < 10) {
        printf("%d ", n);
        return;
    }
    pr(n / 10);
    printf("%d ", n % 10);
}
int main() { pr(1234); return 0; }
① 往下压：每层去掉一位
pr(1234)四位，不满足 n < 10，先调 pr(123)
pr(123)三位，继续调 pr(12)
pr(12)两位，继续调 pr(1)
pr(1)只剩一位，输出 1 后 return，这是出口
② 往回弹：从倒数第二位开始输出
进 pr(1234) 进 pr(123) 进 pr(12) 进 pr(1)　输出 1 pr(1) 返回 输出 2 输出 3 输出 4
为什么正好正序压下去的顺序是 1234、123、12、1，弹回来就变成 1、12、123、1234。每层输出的是自己的末位，合起来就是 1 2 3 4。
汉诺塔：三步就能说清

三根柱子，n 个盘子从 a 挪到 c，每次只能挪一个，大的不能压小的。

void hanoi(int n, char a,
           char b, char c)
{
    if (n == 1) {
        printf("%c->%c\n", a, c);
        return;
    }
    /* ① 上面 n-1 个挪到 b */
    hanoi(n - 1, a, c, b);
    /* ② 最大的搬到 c */
    printf("%c->%c\n", a, c);
    /* ③ 再把 n-1 个搬过来 */
    hanoi(n - 1, b, a, c);
}
A->C A->B C->B A->C B->A B->C A->C 共 7 步
思路就三句上面 n−1 个挪到 b，最大的挪到 c，再把 n−1 个挪到 c。
n 个盘子2 的 n 次方减 1 步。n = 64 时，每秒一步也要几千亿年。
看清这个函数一次调用里出现了两次对自己。前面几题的递归只有一条递推线，这里开成两叉，但走的还是同一套：压下去，触底，弹回来。
走一遍：三个盘子怎么挪
void hanoi(int n, char a,
           char b, char c)
{
    if (n == 1) {
        printf("%c->%c\n", a, c);
        return;
    }
    hanoi(n - 1, a, c, b);
    printf("%c->%c\n", a, c);
    hanoi(n - 1, b, a, c);
}
int main()
{
    hanoi(3, 'A', 'B', 'C');
    return 0;
}
七步，每一步都是「让小的让路，搬大的」
第几步动作在干什么
1A->C最小的先让路
2A->B第二大的挪到 B
3C->B小的压回 B，腾出 A
4A->C最大的落到 C
5B->A小的再让路
6B->C第二大的挪到 C
7A->C小的归位，完成
看出结构第 1~3 步是「把上面两个从 A 搬到 B」，第 4 步搬最大的，第 5~7 步是「把上面两个从 B 搬到 C」。三步一套，套里又套着三步。
n 个盘子2 的 n 次方减 1 步。n = 3 是 7 步，n = 64 就是几千亿年。
斐波那契：先看它算了多少遍

数列是 1、1、2、3、5、8……后一个等于前两个相加。写成递归只有一行，但这一行代价不小。

int calls = 0;        /* 计数 */
long fib(int n)
{
    calls++;            /* 记一笔 */
    if (n <= 2) return 1;
    return fib(n - 1) + fib(n - 2);
}
数法很简单函数第一行加一句 calls++，每进一次就加一。main 里先清零，调完 fib 再读它。

fib(3)2算了两遍

重复在哪fib(5) 要 fib(4) 和 fib(3)；fib(4) 又要 fib(3)。左边这支算过的 fib(3)，右边这支从头再算一遍。同一个值来回算，往下越多重复越凶。

n 一大就顶不住：fib(10) 要调 109 次，fib(20) 要调 13529 次，fib(30) 近三百万次。所以这题规矩是：递归版背下来，真跑用循环。循环两个变量，n = 50 也是眨眼的事。

五个常见错误
① 忘了写出口return age(n-1)+2; 一路减到负数也不停。编译不报错，运行即崩。
② 出口永远走不到写 if (n == 0)，但每次减 2，从 5 开始只会到 1、−1。先检查出口能不能被走到。
③ 忘了 return写 n * fact(n-1); 算完就扔了。要有 return 才算交回去。
④ 用递归算大数斐波那契能出结果，但要等到天荒地老。改成循环，两个变量足够。
⑤ 在递归里改全局变量攒结果int s = 0; 写在函数外面，每层都往 s 上加一个 n。第一次调 addTo(3) 得 6，不清零再调一次就是 12。累加要么用返回值往上传，要么每次调用前自己清零。
这五条的共同点①②③ 是出口和返回值没交代清楚，④⑤ 是选错了工具。写完先拿 n=1 走一遍，前三条当场就露头。
随堂检测
第 1 题　递归的必要条件

下面哪一条是递归必须有的（单选）：

A. 有返回值
B. 函数体里调用了自己
C. 用了 if 语句
D. 参数是 int 类型
看解析
选 B。递归要两样：自己调自己、有出口。A 不对，void 函数照样能递归；C 只是写出口最常用的手段，不是必须；D 跟递归毫无关系。
第 2 题　age(3) 是几
int age(int n)
{
    if (n == 1) return 10;
    return age(n - 1) + 2;
}

age(3) 的值是（单选）：

A. 10
B. 12
C. 14
D. 16
看解析
选 C。往回算：age(1)=10，age(2)=10+2=12，age(3)=12+2=14。从 1 到 3，一共加了两次 2。
第 3 题　这段输出什么
void f(int n)
{
    if (n == 0) return;
    f(n - 1);
    printf("%d", n);
}

调用 f(3)，输出是（单选）：

A. 321
B. 123
C. 3
D. 不输出
看解析
选 B。printf 写在递归调用之后，先一路压到 f(0) 返回，弹回来时依次执行 printf，输出的是 1、2、3。要是把 printf 挪到 f(n-1) 前面，答案就变成 A 的 321。
第 4 题　toBin(13) 输出什么

toBin(13) 的输出是（单选）：

A. 1011
B. 1101
C. 101
D. 13
看解析
选 B。13 的二进制是 1101。printf 写在递归调用之后，先一路压到 toBin(0)，弹回来时从最高位往低位依次输出 1、1、0、1。把 printf 挪到调用前面，得到的才是 A 的 1011；C 漏了最高位的 1；D 根本没转换。
本讲小结
  • ① 嵌套调用函数里调另一个函数，谁用得上谁去调
  • ② 调用栈同一时刻只有一个函数在跑，其余都在等它的结果
  • ③ 递归两条件自己调自己 + 有出口，缺一条就崩或者不成其为递归
  • ④ 两个阶段递推往下挂式子，触底，回归往上代入，一层一个结果
  • ⑤ 栈帧各自独立每一层的 n 是各自的变量，改不到别人
  • ⑥ 输出位置写在递归前是倒序，写在递归后是正序
一句话递归的语法就两行。要花时间的是想清楚哪一层在等、哪一层先算。这一点清楚了，后面的递归题都是同一套走法。
