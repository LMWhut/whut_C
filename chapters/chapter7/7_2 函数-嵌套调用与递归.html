一道绕人的年龄题
题目 五个人坐成一排。问第 5 个人多大，他说：我比第 4 个人大 2 岁。
问第 4 个人，他说：我比第 3 个人大 2 岁。
问第 3 个人，他说：我比第 2 个人大 2 岁。
问第 2 个人，他说：我比第 1 个人大 2 岁。
问第 1 个人，他说：我 10 岁。
第 5 个人多大？
只能这么问 想知道第 5 个，得先知道第 4 个；想知道第 4 个，得先知道第 3 个。 一路问下去，问到第 1 个，答案才出来。
五句话一模一样 「比前一个人大 2 岁」，只换了编号。同一件事做四遍。
这就是递归 要解决的问题，可以写成「同样的问题，规模小一号」。一直小到不用再问为止，答案就有了。
顺着往下问
5age(5) = age(4) + 2
4age(4) = age(3) + 2
3age(3) = age(2) + 2
2age(2) = age(1) + 2
1age(1) = 10　← 问到这儿打住
问了四层，一个数都没算出来 每一层都在等下一层的答案。从第 5 个一路问到第 1 个，谁也没给结果。
最后一行不一样 age(1) = 10 不用再问任何人，答案直接写死在这儿。 这一行叫出口，也叫终止条件。
然后往回算 12、14、16、18，一步一个，四步就回来了。
写成函数
int age(int n)
{
    int c;
    if (n == 1)
        c = 10;              /* 出口 */
    else
        c = age(n - 1) + 2; /* 调自己 */
    return c;
}
main 里怎么用 printf("%d\n", age(5));
跟调普通函数一样，看不出什么特别。
两行各管一件事 if 那行管「什么时候停下」， else 那行管「没停下的时候，把问题换成小一号的自己」。

递归的两条硬条件

①自己调自己

函数体里出现自己的名字，把问题缩成小一号的同款问题。

②有出口

某个条件下不再调用自己，直接给出答案。

少第一条 没有自己调自己，那就只是一个普通函数，跟递归没关系。
少第二条 程序会一直往下调，直到把内存里的栈用光，然后崩溃。这个现象叫栈溢出。
写递归先想哪一条 先想出口。出口写对了，剩下的只是把大问题写成小一号的自己。
少一条会怎样
/* 出口那一行被删了 */
int age(int n)
{
    return age(n - 1) + 2;
}
age(5) → age(4) → age(3) → … 一路往下，停不下来 程序崩溃：stack overflow
为什么是崩溃，不是死循环 循环占的地方始终是那几个变量，递归不是。每调一次，系统要在栈上开一格存现场： 这一层的 n 是多少、回来接着执行哪一行。格子只加不减，栈满了就崩。
编译器不管这事 语法完全正确，编译能过，跑起来才炸。这类错只能靠写之前想清楚出口来避免。
现场怎么认 程序刚跑就退出，一个字都没输出，或者弹出「已停止工作」。先回头找出口。
n! 的递归定义
数学上这么写
n! = 1当 n ≤ 1
n! = n × (n−1)!当 n > 1
一行对一行 第一行是出口，第二行是自己调自己。代码几乎是照着抄下来的。
自己展开一遍
fact(4) = 4 × fact(3)
　　　　= 4 × (3 × fact(2))
　　　　= 4 × (3 × (2 × fact(1)))
　　　　= 4 × (3 × (2 × 1)) = 24 
long fact(int n)
{
    if (n <= 1) return 1;   /* 出口 */
    return n * fact(n - 1); /* 递推 */
}
两个词，分清楚 递推：往下走，把待算的式子一层层挂起来。
回归：碰到出口往回走，一层层把值代进去。
为什么写 <= 不写 == 数学上 0! = 1。出口写成 n <= 1，把 0 一并挡住； 只写 n == 1 的话，传 0 进来会一路减到负数，栈越压越深。
fact(4)：压进去，再弹回来
long fact(int n){    if (n <= 1) return 1;    return n * fact(n - 1);}
看这两行 往下压时停在第 4 行等右边；只有触底那次才走第 3 行。
容易想错 不是「n 减到 1 就乘 1」，每层乘的是自己那个 n。

　嵌套调用递归调用
谁在调谁调的是别的函数函数体里出现自己的名字
走到头以后一层层剖下去，干完就结束触底后沿原路一层层返回来
会不会停不下来不会，链条是有限的会，出口写错就永远停不下来
本讲的例子main → sum(10) → fac(i)fact(4) → fact(3) → fact(2)
嵌套：调的是别人
/* sum 里这一句 */

递归：调的是自己
/* fact 里这一句 */

结论 递归也是嵌套调用，特殊在调用者和被调用者是同一个函数。前面讲的「谁在跑、谁在等」原样适用。
递归和循环，怎么选
　循环递归
代码长度要自己维护计数器、累加变量通常更短，跟数学式子接近
读起来一步一步走，踏实想通结构就一眼，想不通就绕
运行开销小，几个变量而已大，每层都要开一个栈帧
最大隐患边界写错，多跑或少跑一次出口写错，栈溢出
什么时候用次数明确，能从头数到尾问题本身就是一层套一层
记住这一条 能用循环顺手写出来的，就用循环。递归留给那些用循环写会别扭的题。
什么样的题适合递归
1能不能写成「自己 + 小一号的自己」
n! 写成 n × (n−1)!，二进制写成「先转 n/2，再输出 n%2」。
2有没有天然的最小情形
1! = 1、n 只剩一位数、盘子只剩一个。有，才停得下来。
3每次是不是真的变小了
n−1、n/2 都会变小。写成 fact(n) 里调 fact(n)，永远不缩小，等于没出口。
三问都过 这题就可以用递归。少一条，先回头把条件补上，别急着写代码。

十进制转二进制
循环版：得自己找最高位
int p = 1;
while (p * 2 <= n) p *= 2;  /* 最高位 */
while (p > 0) {
    printf("%d", n / p % 2);
    p /= 2;
}
为什么多一段 循环从低位往高位算，可输出却要先给高位。只好先算出最高位，再倒着往下取。
递归版：栈替你排好队
void toBin(int n)
{
    if (n == 0) return;
    toBin(n / 2);      /* 先转高位 */
    printf("%d", n % 2);
}
toBin(13) → 1101
好在哪 不用找最高位。每层的 n 存在自己栈帧里，弹回来正好从高位输出到低位。
两个函数同名，是两套方案，别同时放进一个文件。传 13 进递归版，弹回来依次输出 1、0、1、1。
走一遍：toBin(13) 为什么输出 1101

汉诺塔：三步就能说清
void hanoi(int n, char a, char b, char c)
{
    if (n == 1) {
        printf("%c->%c\n", a, c);
        return;
    }
    hanoi(n - 1, a, c, b); /* 移开上面 */
    printf("%c->%c\n", a, c); /* 最大的 */
    hanoi(n - 1, b, a, c); /* 再搬过去 */
}
A->C A->B C->B A->C B->A B->C A->C 共 7 步
思路就三句 上面 n−1 个挪到 b，最大的挪到 c，再把 n−1 个挪到 c。
n 个盘子 2 的 n 次方减 1 步。n = 64 时，每秒一步也要几千亿年。

五个常见错误
① 忘了写出口 return age(n-1)+2; 一路减到负数也不停。编译不报错，运行即崩。
② 出口永远走不到 写 if (n == 0)，但每次减 2，从 5 开始只会到 1、−1。先检查出口能不能被走到。
③ 忘了 return 写 n * fact(n-1); 算完就扔了。要有 return 才算交回去。
④ 用递归算大数斐波那契 能出结果，但要等到天荒地老。改成循环，两个变量足够。
⑤ 在递归里改全局变量攒结果 int s = 0; 写在函数外面，每层都往 s 上加一个 n。 第一次调 addTo(3) 得 6，不清零再调一次就是 12。
累加要么用返回值往上传，要么每次调用前自己清零。

答案 1 · 递归的必要条件
选 B。递归要两样：自己调自己、有出口。A 不对，void 函数照样能递归；C 只是写出口最常用的手段，不是必须；D 跟递归毫无关系。

答案 2 · age(3) 是几
选 C。往回算：age(1)=10，age(2)=10+2=12，age(3)=12+2=14。从 1 到 3，一共加了两次 2。

本讲小结
  • ① 嵌套调用函数里调另一个函数，谁用得上谁去调
  • ② 调用栈同一时刻只有一个函数在跑，其余都在等它的结果
  • ③ 递归两条件自己调自己 + 有出口，缺一条就崩或者不成其为递归
  • ④ 两个阶段递推往下挂式子，触底，回归往上代入，一层一个结果
  • ⑤ 栈帧各自独立每一层的 n 是各自的变量，改不到别人
  • ⑥ 输出位置写在递归前是倒序，写在递归后是正序
递归的语法就两行。要花时间的是想清楚哪一层在等、哪一层先算。
